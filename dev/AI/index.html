    MCP в Vanessa Automation¶

    Быстрый старт¶

    Для начала использования MCP в Vanessa Automation выполните следующие шаги:

    1. Настройте LLM с поддержкой MCP. У вас должна быть работающая LLM, к которой можно подключить MCP инструменты. Например, VSCode + плагин Cline — это среда, где вы пишете промты.

    2. Установите расширение client_mcp в базу менеджера тестирования. В базу менеджера тестирования необходимо поставить расширение из проекта. В базе расширение должно быть установлено под именем client_mcp и активно — по этому имени Vanessa Automation находит его при старте.

    3. Запустите сеанс 1С как менеджер тестирования и откройте в нём Vanessa Automation. Сеанс обязательно должен быть запущен с ключом /TestManager — только такой сеанс является менеджером тестирования; на работу в этом режиме рассчитаны MCP-инструменты управления клиентом тестирования. Что и где именно запускать — в разделе Запуск MCP сервера: что и где запускать. При старте Vanessa Automation зарегистрирует свои инструменты MCP (если расширение client_mcp найдено).

    4. MCP сервер запустится сам. Если Vanessa Automation найдёт в базе расширение client_mcp, она сама запустит сервер MCP — отдельно запускать его не нужно. Условия автозапуска, порт и ручной запуск описаны в разделе Запуск MCP сервера: что и где запускать.

    5. Настройте MCP клиент в вашей IDE. В вашей IDE, где работает LLM, необходимо прописать настройки MCP сервера, который запущен в менеджере тестирования. В инструкции ниже приведены примеры настроек для плагина Continue (для VSCode), плагина Cline и плагина Roo Code (тоже для VSCode).

    6. Включите внешнюю компоненту VanessaExt. В Vanessa Automation необходимо включить использование внешней компоненты VanessaExt.

    7. Установите расширение VAExtension. В базу клиента тестирования необходимо добавить расширение VAExtension. Для MCP-инструмента restart_vanessa это же расширение должно быть установлено и активно в базе менеджера тестирования; чтобы перезапуск ждал фактического закрытия старой формы, нужна версия 1.44 или выше — с более старым расширением действует прежняя схема.

    8. Настройка завершена. После выполнения всех шагов MCP готов к работе.

    Запуск MCP сервера: что и где запускать¶

    Сервер MCP — это не отдельная программа. Он поднимается внутри сеанса 1С:Предприятие, в котором открыта Vanessa Automation, поэтому скачивать или устанавливать его отдельно не нужно.

    Где запускать¶

    Всё запускается на том компьютере, где должен работать менеджер тестирования — как правило, это тот же компьютер, на котором установлена ваша IDE с LLM. Сеанс 1С:Предприятие с открытой Vanessa Automation становится менеджером тестирования, а сервер MCP принимает подключения от вашей IDE.

    Что запускать: сеанс 1С в режиме менеджера тестирования¶

    Запускается обычный сеанс 1С:Предприятие, но обязательно с ключом /TestManager — только сеанс с этим ключом является менеджером тестирования. Если запустить Vanessa Automation в обычном сеансе (без ключа), менеджером тестирования он не станет: сервер MCP в нём может подняться, но MCP-инструменты управления клиентом тестирования рассчитаны на сеанс менеджера тестирования.

    Пример запуска из командной строки:

    "C:\Program Files\1cv8\8.3.27.2130\bin\1cv8c.exe" ENTERPRISE /IBConnectionString "File=""c:\Bases\8.3.27"";" /TestManager /Execute "C:\Commons\rep\vanessa-automation\vanessa-automation.epf"
    • 1cv8c.exe — тонкий клиент (исполняемый файл толстого клиента — 1cv8.exe). Путь к исполняемому файлу подставьте от своей версии платформы.
    • /IBConnectionString — строка соединения с базой менеджера тестирования (в примере — файловая база c:\Bases\8.3.27).
    • /TestManager — ключ запуска сеанса в режиме менеджера тестирования (в проекте встречается и написание /TESTMANAGER).
    • /Execute — путь к файлу vanessa-automation.epf.

    Эту же команду можно сохранить в ярлык или bat-файл, подставив свои пути. Для отладки сеанс можно запускать из конфигуратора, добавив /TestManager в дополнительные параметры запуска.

    Если Vanessa Automation уже открыта в обычном сеансе, её можно перезапустить как менеджер тестирования — командой Перезапустить как менеджер тестирования в командной панели окна Vanessa Automation (дополнительное подменю). Команда видна, только пока сеанс не является менеджером тестирования.

    Автозапуск сервера MCP¶

    Отдельно запускать сервер MCP не нужно: если Vanessa Automation находит в базе расширение client_mcp, она запускает сервер MCP сама — при старте, после регистрации инструментов MCP.

    Автозапуск работает, когда выполнены все условия:

    • в базе, где запущен сеанс, установлено и активно расширение client_mcp;
    • на закладке AI настроек Vanessa Automation включена настройка «Запускать сервер MCP при запуске VA» (включена по умолчанию);
    • Vanessa Automation не запущена в режиме самотестирования.

    Сервер поднимается на порту из настройки «Порт сервера MCP» на той же закладке AI (по умолчанию 9874; если порт не задан или задан неверно, используется 9874). Обе настройки можно задать и параметрами StartMCPServerOnVAStartup и MCPServerPort, например в файле VAParams.json.

    Если сервер уже запущен (например, его запустили вручную), автозапуск ничего не делает и настройка «Порт сервера MCP» не применяется.

    Автозапуск не действует, если свой MCP-транспорт установил внешний плагин (внешний фасад расширения) — в этом случае транспортом управляет плагин.

    Ручной запуск сервера MCP¶

    Если автозапуск отключён или сервер нужно запустить вручную:

    • запустите сервер из формы управления MCP расширения client_mcp (кнопка запуска сервера);
    • либо попросите расширение запустить сервер сразу при старте сеанса, передав в командной строке:
    "C:\Program Files\1cv8\8.3.27.2130\bin\1cv8c.exe" ENTERPRISE /IBConnectionString "File=""c:\Bases\8.3.27"";" /TestManager /Execute "C:\Commons\rep\vanessa-automation\vanessa-automation.epf" /C "runMcp;mcpPort=9874"

    В параметре mcpPort можно указать свой порт сервера, но он должен совпадать с портом в настройках MCP-клиента (в примерах конфигов ниже — 9874).

    Диагностика MCP в журнале регистрации¶

    Если нужно разобрать работу MCP (загрузку фич, запуск сценариев, проверку синтаксиса), включите на закладке AI настройку «Записывать служебные данные MCP в журнал регистрации» (параметр AIЗаписыватьСлужебныеДанныеВЖР / WriteMCPServiceDataToEventLog). По умолчанию настройка выключена.

    События пишутся в журнал регистрации базы, где запущена Vanessa Automation, с префиксом VanessaAutomation.MCP. и уровнем «Информация». В данных события передаются только служебные поля: режим, идентификатор вызова, путь к файлу, номера строк, статусы и признаки. Тексты ошибок и значения полей тестируемого приложения в события MCP не записываются. Записи удобно отбирать по префиксу события VanessaAutomation.MCP. (в инструменте get_event_log_manager — event_match_type: starts_with).

    При включённой настройке вызовы инструментов Vanessa Automation, у которых не было события начала, пишутся событием VanessaAutomation.MCP.Инструмент.Запрос: имя инструмента, идентификатор вызова и имена параметров. Значения параметров не записываются. У инструментов check_syntax, open_feature_file, load_features, execute_feature_step, run_scenario, stop_scenario и restart_vanessa остаются их прежние события начала (СинтаксКонтроль.Запрос, ОткрытиеФичаФайла.Запрос, Шаг.Запрос, Сценарий.Запрос, Сценарий.Остановка, Перезапуск.Вызов, Перезапуск.Запрос). В ветках отказа run_scenario, open_feature_file и load_features, которые завершаются до своего события начала, запись о вызове может отсутствовать. Инструменты, зарегистрированные расширением (например, infobase_info), этим событием не покрываются.

    При частом опросе get_vanessa_automation_state и get_test_results журнал растёт, а каждая запись выполняется серверным вызовом и может добавлять задержку: включайте настройку на короткое время диагностики. Вызов самого get_event_log_manager тоже пишется в журнал и может попасть в читаемую выборку.

    Проверка¶

    Запущенный сервер MCP отвечает по адресу http://<компьютер менеджера тестирования>:<порт>/mcp. Если IDE работает на том же компьютере, в настройках MCP клиента указывается http://localhost:9874/mcp — примеры конфигов для разных плагинов приведены ниже. Через MCP доступно управление сеансом 1С, поэтому не открывайте порт сервера во внешнюю сеть — для удалённого подключения используйте доверенную сеть.

    🚀 Реальный проект покрытия тестами¶

    🔄 Полный workflow от ТестПлан.MD до готовых feature-файлов¶

    ВХОДЫ (пользователь):
├── ТестПлан.MD           — тесты в свободной форме
├── dt/<Эталон>.dt        — эталонное состояние базы
└── ПараметрыКонфигурации.MD — пути проекта

         ↓

УПРАВЛЯЮЩИЙ АГЕНТ (оркестратор):
1. Парсит ТестПлан.MD → СПИСОК_СЦЕНАРИЕВ
2. Для каждого сценария запускает цепочку субагентов

         ↓

ВЫХОДЫ (по каждому сценарию):
├── data/АнализДанных_<NN>.MD            ← от АнализДанныхИИнтерфейса
├── research/РезультатИсследования_<NN>.MD ← от Исследователя
├── rewiew/rewiew_<NN>_Researcher.md     ← от Код-Ревьюера (Researcher)
├── features/<NN>_<...>.feature         ← от Писателя
├── rewiew/rewiew_<NN>_Writer.md         ← от Код-Ревьюера (Writer)
├── restore/Restore_<NN>.MD             ← от АдминистраторБазы
└── writer/ПисательСценариев_<NN>.MD    ← лог работы Писателя

         ↓

НАКОПЛЕНИЕ ЗНАНИЙ:
└── Memory.MD  ← по итогам работы сюда записываются
                  новые знания о конфигурации

    📋 Шаги для запуска нового тестового проекта¶

    1. Создать каталог проекта (например, C:\Commons\rep\AI\testERP7\).
    2. Скопировать шаблоны из examples/МультиАгент/:
    3. InstructionsResearch.md
    4. InstructionsWriteScenario.md
    5. ПодготовкаУправляющегоАгента.MD
    6. ПромптыСубагентов/ (целиком)
    7. Чеклисты/ (целиком)
    8. Создать ПараметрыКонфигурации.MD и заполнить пути.
    9. Подготовить DT-эталон — положить в dt/<Эталон>.dt.
    10. Написать ТестПлан.MD — заполнить тесты в свободной форме.
    11. Запустить Управляющего Агента (см. ПодготовкаУправляющегоАгента.MD).

    InstructionsWriteScenario.md копируется обычно без изменений

    Автотесты MCP-инструментов¶

    Для MCP-слоя есть отдельный набор фич и тестовая библиотека. Они не требуют клиента тестирования и не выполняют реальных действий: инструмент сообщает намерение, а guard в продакшн-коде останавливает вызов до первого действия.

    Перед запуском нужны собранный MCP.epf и остановленный MCP-сервер: Дано проверяет MCPСерверЗапущен() как жёсткий gate.

    • Фичи: features/Core/MCPAutotests.
    • Библиотека шагов: features/Libraries/MCP.
    • Запуск: стандартным проигрывателем фич Vanessa Automation после сборки MCP.epf.

    Шаги библиотеки:

    Дано я подготавливаю тестовый транспорт MCP
Когда я вызываю MCP-инструмент "manage_form_elements" в режиме "Намерение" с параметрами
    | Имя          | Значение     |
    | action       | click_button |
    | element_name | КнопкаОК     |
Тогда MCP-инструмент вернул намерение "client.form.action"
И MCP-инструмент не выполнял реальных действий

    Режимы: Намерение (тестовый транспорт), Проверка (валидация без реального действия), План (синоним Намерение). Режим Выполнить (L3) пока не реализован.

    Доступные инструменты:¶

    Ниже приведена таблица всех доступных MCP инструментов Vanessa Automation, отсортированная по имени инструмента.

    Инструмент Описание
    activate_process_os Активизирует окно процесса операционной системы: выводит его на передний план и передаёт ему фокус. Аналог шагов <И я активизирую процесс "PID"> и <И я активизирую процесс по заголовку "Заголовок">; полная аналогия с шагом по заголовку — при поиске с маской заголовок, без маски отбор шире — по подстроке. Нужно передать один из параметров: pid (положительное число; активизировать главное окно процесса) или window_title (найти процесс по заголовку или части заголовка окна; поддерживаются маски с *, например Блокнот; поиск без учёта регистра; маска проверяется на полное совпадение строки, поэтому для поиска по части строки оборачивайте выражение в * с обеих сторон). Параметры pid и window_title взаимоисключающие. Полезно перед всем, что работает с активным окном: эмуляция клавиатуры, ввод текста, шаги UI Automation, снятие скриншота. Для работы нужна включённая внешняя компонента VanessaExt. Не работает в веб-клиенте. Клиент тестирования не требуется.
    check_syntax Проверяет синтаксис Gherkin в указанном feature-файле. Параметр filePath обязателен; принимается только файл с расширением .feature (каталог и другие расширения отклоняются как INVALID_PARAMS и не меняют текущий каталог фич). Возвращает Markdown с найденными ошибками: неизвестные шаги, структурные проблемы, ошибки ключевых слов. Можно проверять любой feature-файл, даже если он не открыт в редакторе. Проверка оставляет проверяемый файл открытым и активным: если файл не был открыт, открывается новая вкладка; если файл уже открыт в редактируемой вкладке, она активируется; если только в diff-вкладке, создаётся редактируемая вкладка. Прежняя активная вкладка остаётся открытой. Текущим файлом фич становится проверяемый файл, поэтому последующие инструменты работают с ним. В Markdown-ответе указывается, изменилась ли активная вкладка, какая вкладка была активна до и после, была ли открыта новая вкладка и был ли файл открыт до проверки. При ошибке обработки результата загрузки или таймауте ожидания загрузки вкладка проверяемого файла не закрывается, а в текст ошибки добавляется фактическое состояние вкладок редактора.
    close_test_client Закрывает сеанс клиента тестирования по имени профиля. Если профиль не указан — закрывает текущий подключённый профиль. Используйте для завершения работы с клиентом тестирования после выполнения тестов.
    execute_feature_step Выполняет шаг из .feature файла по номеру строки. Если фича уже загружена, выполняет шаг без повторной загрузки; иначе загружает файл. Параметры reload (принудительная загрузка) и details (расширенный ответ: режим, номера строк, файл дерева). Внешние изменения файла на диске не проверяются. Если идёт загрузка, возвращает ACTION_FAILED с причиной BUSY — повторите вызов после её завершения.
    execute_form_actions Выполняет последовательность действий с элементами формы клиента тестирования. Позволяет выполнить несколько действий за один вызов инструмента. Параметр actions_json (обязательный) - JSON-строка с массивом действий. Каждое действие в массиве содержит: action - тип действия (click_button, input_text, и т.д.), element_name - имя элемента формы, table_name - имя таблицы (если элемент в таблице), value - значение для ввода/выбора, другие параметры в зависимости от действия. При возникновении ошибки выполнение прерывается. Ответ - компактный отчёт: одна строка на выполненное действие вида 'N действие адрес ok' (например, '1 set_value Менеджер=Admin ok ("Admin")'); полезная нагрузка read-действий (содержимое списка у get_dropdown_state, данные строк у get_selected_rows) и ошибки приводятся полным текстом. Модальные диалоги: диалог проверяется перед каждым действием, после последнего действия и при ошибке действия (диалог может появиться с задержкой - после цепочки асинхронных обработчиков). Появление модального диалога приостанавливает цепочку: результат возвращается со статусом paused_modal_dialog (это не ошибка), в нём - выполненные действия, текст диалога, его кнопки и машиночитаемый остаток цепочки (блок json), выполненные действия повторять не нужно. Диалоги не закрываются автоматически: ожидаемый диалог закрывайте действием manage_modal_dialog прямо в цепочке сразу после действия, которое его вызывает; неожиданный - ответом на паузу (manage_modal_dialog через manage_form_elements) и продолжением остатка. Окна 'Выбор типа данных' и 'Список значений' диалогами не считаются - с ними работает вызывающая сторона. После add_row на динамическом списке активна форма создания элемента: цепочку нужно остановить и продолжить после записи и закрытия формы; дальнейшие действия с этой таблицей в той же цепочке не выполнятся. Веб-клиент: не поддерживается. Требует подключённого клиента тестирования.
    find_form_elements Ищет элементы в активном окне клиента тестирования платформенным методом НайтиОбъекты: по заголовку, по имени элемента или по обоим (параметр search_by: all/title/name; по умолчанию all). Символ * - маска (например, Товар). Для каждого найденного элемента выводится заголовок, внутреннее имя, тип и вид, родитель первого уровня, а также имя табличной части, если элемент находится в таблице (учитываются колонки, вложенные в группы внутри таблицы). Параметр search_string обязателен; limit ограничивает число элементов в ответе (по умолчанию 50, 0 - без ограничения). Поиск идёт только по активному окну; элементы на ещё не открытых закладках (страницах формы) могут не находиться - переключите закладку (страницу) (switch_tab). Пустой результат - не ошибка. Требует платформы 8.3.25 и выше и подключённого клиента тестирования. Это поиск элементов формы клиента тестирования (не путать с find_elements UI Automation в manage_uiautomation).
    frequently_used_steps Возвращает информацию о том какие шаги чаще используются по статистике больших проектов. В начале идут часто используемые шаги, далее идут более редко используемые шаги. Возвращает представление шага, описание шага, тип шага. Также возвращает информацию сколько всего шагов есть в накопленной статистике.
    get_active_form_element Возвращает идентичность активного элемента формы клиента тестирования в модели TestClient: клиент, окно, форма, элемент (имя, заголовок, тип, вид), а для таблицы - таблица, текущая колонка (если определена) и сведения о выделенных строках. Read-only: не перемещает фокус, не открывает формы и не выполняет шаги. Если элемент не в фокусе или активное окно не является формой, возвращается явное пустое состояние, а не ошибка. Ответ - Markdown и блок JSON; element_id имеет вид <ИмяФормы>/<ИмяЭлемента> или <ИмяФормы>/<ИмяТаблицы>/<ИмяКолонки> (это идентификатор TestClient, не element_id UI Automation). Параметр format=json возвращает машиночитаемый объект: schemaVersion (1.1), runId, ok, scenarioId/treeRowId, имя сценария и фичи, статус, isComplete (есть финальный статус или результат одиночного шага), ошибку, шаги с id/lineNumber/status/error и счётчики; при отсутствии результата ok=false, isComplete=false и reason (result_not_ready/no_results/scenario_not_run); значения параметров шага в JSON не выводятся.
    get_va_settings Читает настройки Vanessa Automation в уже работающем сеансе. Действия (параметр action): list (по умолчанию) — список настроек с фильтрами и поиском по частичному совпадению, get — одна настройка по key или path (тип, текущее значение, значение по умолчанию, допустимые значения, состояние элемента формы, зависимости), groups — список групп. Поиск query не учитывает регистр, приводит ё к е и игнорирует разделители _ - пробел и точку; ищет по русскому имени, английскому json-ключу, path и синониму (например, query=allur находит настройки отчёта Allure). Фильтры: match (contains/starts_with/exact), group, path_prefix, keys, available_only; пагинация — limit (по умолчанию 50, максимум 200, 0 — все) и offset. Состав ответа: include_values (по умолчанию true), include_defaults, include_allowed_values, include_ui_state. Для каждой настройки возвращаются kind, settable, read_only_reason, requires_restart, requires_handler и подсказки. Значения возвращаются как есть, без маскирования паролей и токенов. Клиенты тестирования и GlobalVars в инструмент не входят (manage_test_client_profiles/manage_test_client и manage_variables); КаталогФич доступен только для чтения (open_feature_file/load_features/run_scenario); lifecycle-ключи помечены ACTION_ONLY. Формат ответа — format=markdown (по умолчанию) или json.
    get_vanessa_automation_state Возвращает текущее состояние Vanessa Automation (по умолчанию в формате Markdown, при format=json — машиночитаемый JSON): выполняется ли сценарий, текущая фича (имя, путь, язык, теги), текущий сценарий (имя, статус, теги, treeRowId), текущий шаг (id, текст, значения параметров, номер строки, статус; stepFile — файл шага, isSubScenarioStep — признак шага подсценария, для подсценария subScenarioCallLine — строка вызова, callId — идентификатор вхождения вызова; статус Running означает, что шаг выполняется), подключён ли клиент тестирования. Результат сценария выводится компактно: статус, время, упавший шаг, краткая ошибка, один блок технических данных и подробности ошибки в details; полная детализация — в get_test_results по scenarioId. Данные о фиче, сценарии и шаге относятся к прогону, а не к файлу в редакторе (файл редактора — manage_editor). Параметр format=json возвращает машиночитаемый объект: schemaVersion (1.1), runId, ok, текущую фичу (tags — массив строк), сценарий (isComplete — есть финальный статус или результат одиночного шага), текущий шаг (name/lineNumber/id/status/statusRaw), упавший шаг (name/lineNumber/id/status/statusRaw/error), счётчики, stateAvailable/stateReason; полный список шагов — в get_test_results; значения параметров шага в JSON не выводятся.

Результат можно использовать для управления окнами с помощью инструмента window_management (активизировать, закрыть, открыть навигационную ссылку), либо для получения данных из текущего окна get_active_window_data. Результат нельзя использовать для получения скриншота окна, т.к. список внутренних окон клиента тестирования и список окон с точки зрения операционной системы - это разные вещи.

Параметр window_title определяет с какого окна нужно снять скриншот, т.к. у одного клиента тестирования может быть несколько окон. Параметр обязательный. Чтобы получить список доступных окон для снятия скриншота надо вызвать get_window_list_os. Параметр color_mode определяет режим цвета: grayscale (черно-белый, по умолчанию) или color (цветной).     input_text_to_active_field Вводит текст в активное поле, эмулируя ввод с клавиатуры через внешнюю компоненту VanessaExt. Имя элемента формы указывать не нужно: текст вводится в то окно, которое сейчас активно в операционной системе. Если текст должен попасть в неактивное окно, передайте activate_window=true - тогда перед вводом будет активизировано окно клиента тестирования, либо окно, заданное параметрами pid или window_title. Раскладка клавиатуры не важна. Вводятся только символы: клавиши Enter, Tab и другие не эмулируются, для них используйте manage_uiautomation press_keys. Для длинного или многострочного текста поместите его в буфер обмена (manage_clipboard, action='set_text') и вставьте сочетанием Ctrl+V (manage_uiautomation, action='press_keys'). Эмуляция ввода не сообщает об ошибках и может быть прервана, поэтому после ввода проверьте значение поля (get_form_element_data). Пока идёт ввод, не вызывайте инструменты, которые работают с тем же активным окном или вводом: activate_process_os, manage_uiautomation и другие отложенные операции с окнами. speak_text на ввод не влияет и доступен. При выполнении сценариев инструмент отказывает - сначала остановите сценарии (stop_scenario). Параметры: text (обязательный, максимум 1000 символов), delay (задержка между символами в мс, от 0 до 5000, по умолчанию 100 - примерно 10 символов в секунду; длина текста, умноженная на задержку, не должна быть больше 45000), activate_window (по умолчанию false), pid и window_title (взаимоисключающие, используются только вместе с activate_window=true; в window_title поддерживаются маски с *, маска проверяется на полное совпадение строки, поэтому для поиска по части строки оборачивайте выражение в * с обеих сторон). Требует включённую внешнюю компоненту VanessaExt. Не работает в веб-клиенте и под Linux.
    load_features Устаревший alias для open_feature_file; сохраняет прежний формат ответа и параметр path. Загружает или перезагружает .feature файл. Используйте после того как вы отредактировали .feature файл, чтобы перечитать файл с диска в Vanessa Automation. Построение дерева выполняется асинхронно; инструменты запуска сценариев дожидаются готовности дерева. Если path не указан, перезагружается текущий файл в редакторе.
    manage_app Универсальный инструмент для управления приложением клиента тестирования. Поддерживаемые действия (параметр action): set_file_dialog_result - установить результат диалога выбора файла в клиенте тестирования (параметры: cancel - булево, необязательное, по умолчанию Ложь: Истина = отмена диалога, Ложь = файл выбран; file_name - строка, путь к выбранному файлу, обязателен при cancel=Ложь; filter_index - целое неотрицательное число, необязательный индекс фильтра диалога; при cancel=Истина параметры file_name и filter_index игнорируются). Установленный результат сработает при следующем открытии диалога выбора файла в клиенте тестирования; требует подключённого клиента тестирования (manage_test_client, action='connect'). clear_file_dialog_result - очистить ранее установленный результат диалога выбора файла (не требует параметров; требуется платформа 8.3.25+).
    manage_breakpoints Управление точками останова в Gherkin-сценариях; те же действия доступны через manage_editor (list_breakpoints, toggle_breakpoint, remove_all_breakpoints). Действия: toggle (по умолчанию), remove_all, list. Остановка на точке останова прекращает весь прогон: шаг с точкой останова не выполняется, сценарии после него тоже. Точки учитываются по паре (файл шага, строка), поэтому точка на шаге внутри вызванного сценария срабатывает и при вызове из другого сценария; для такого шага toggle возвращает примечание о семантике (при повторном выполнении шага точка сработает снова); любая строка вызова вложенного подсценария пока не проверяется. line — положительное целое число; без line переключается текущая строка курсора, некорректное значение (0, отрицательное, дробное, нечисловое, пустое) отклоняется как INVALID_PARAMS. list возвращает точки по данным редактора: переключение через toggle видно сразу, изменения мышью могут отображаться с запаздыванием; отдельной строкой выводится число участников следующего прогона. Точки других открытых вкладок показываются отдельным разделом: они учитываются по файлу шага и сработают, если в прогоне выполняются шаги из соответствующего файла; в счётчик текущей вкладки не входят, точки-вставки других вкладок в прогоне не участвуют. remove_all очищает только текущую вкладку; если в других вкладках остались точки, ответ об этом предупреждает. При загрузке или перезагрузке фичи точки останова не переносятся: номера строк могли измениться, поэтому проверьте их заново. Если дерево фич уже загружено, непусто и не соответствует активной вкладке, toggle ставит точку, но предупреждает, что проверка исполняемости строки не выполнялась.
    manage_clipboard Работает с системным буфером обмена операционной системы через внешнюю компоненту VanessaExt. Поддерживаемые действия (параметр action): set_text - поместить текст в буфер обмена (требуется text), get_text - прочитать текст из буфера обмена (при большом объёме вернутся только первые 100000 символов), clear - очистить буфер обмена. Основной сценарий: длинный или многострочный текст нельзя ввести инструментом input_text_to_active_field (лимит 1000 символов), поэтому текст помещают в буфер обмена (action='set_text'), активизируют окно-приёмник (activate_process_os) и вставляют текст сочетанием Ctrl+V (manage_uiautomation, action='press_keys'). Буфер обмена - общий ресурс операционной системы: инструмент затирает то, что пользователь скопировал ранее, а тестируемое приложение или шаг сценария может перезаписать буфер. Если в буфере обмена файлы, а не текст, action='get_text' вернёт список путей к файлам. Если буфер обмена занят другим приложением, текст может вернуться пустым - повторите вызов. Пока идёт работа с буфером обмена, не вызывайте инструменты, которые работают с тем же активным окном или вводом: input_text_to_active_field, manage_uiautomation, activate_process_os. speak_text буфер обмена не использует и доступен. Параметр text обязателен для action='set_text', максимум 100000 символов, многострочный текст передавайте целиком: переводы строк сохраняются. Требует включённую внешнюю компоненту VanessaExt. Не работает в веб-клиенте. Под Linux поддерживается только текст, файлы и картинки недоступны. При запрете синхронных вызовов способ вставки через manage_uiautomation press_keys не работает.
    manage_command_interface Универсальный инструмент для работы с командным интерфейсом 1С:Предприятия.     manage_editor Управление редактором Vanessa Automation. Действия (параметр action): get_state — состояние редактора: вкладки, активный документ, позиция курсора, ошибки, дерево фич; параметры includeContent, includeDocument, includeTabs (по умолчанию true); list_tabs — компактный список вкладок; activate_tab — активировать вкладку; get_tab_content — текст вкладки; save_tab — сохранить edit-вкладку; для активной или деревой .feature-вкладки — как Ctrl+S: записать файл и перезагрузить дерево; пишет файл даже без изменений и возвращает saved, wasModified, treeReloaded, treeReady, treeError; фоновая вкладка другого файла сохраняется без переключения дерева; close_tab — закрыть вкладку; line_info — информация о строке сценария (обязательный lineNumber — положительное целое число); list_breakpoints, toggle_breakpoint (параметр line; без него — текущая строка курсора) и remove_all_breakpoints — точки останова.     manage_form_elements Универсальный инструмент для управления элементами формы клиента тестирования. Внимание: действия выполняются в реальных окнах операционной системы — проверяйте PID процесса и найденный элемент перед кликом; клик эмулируется как реальное нажатие мыши по координатам элемента на экране, поэтому попадает в окно, которое находится в этих координатах на переднем плане (обычно это активное окно): если окно с элементом неактивно или точку клика перекрывает другое окно, клик уйдёт не туда — сначала активизируйте нужное окно инструментом activate_process_os и убедитесь, что элемент не перекрыт. Ввод текста и нажатие клавиш (press_keys) уходят активному окну операционной системы (окну, которое сейчас в фокусе), а не элементу UI Automation. Требует включённую внешнюю компоненту VanessaExt.
    manage_va_settings Изменяет настройки Vanessa Automation в уже работающем сеансе. Действия: set — одна настройка (key/path + value), apply — набор настроек VAParams из file_path или parameters_json (строка JSON), base_path — базовый каталог для относительного пути; ключи КаталогФич и lifecycle-ключи в наборе попадают в out_of_scope. Перед изменением проверяются тип, допустимые значения (для строковых и числовых списков — так же, как для ссылочных), семантика ключа и доступность элемента формы: эффективные Видимость, Доступность и ТолькоПросмотр с учётом родительских групп. Если настройка сейчас не видна, недоступна или доступна только для просмотра, возвращается SETTING_NOT_AVAILABLE (или UI_ELEMENT_NOT_FOUND), значение не меняется; включающая и зависимая настройки (например, отчёт Allure) применяются двумя вызовами set либо одним apply, если включающая есть в том же наборе. Настройки без элемента формы применяются напрямую с предупреждением; в apply настройка, скрытая из-за явно выключенной включающей настройки в том же наборе, пропускается с причиной DEPENDENCY_DISABLED, а в set возвращается SETTING_NOT_AVAILABLE. После штатного загрузчика значение ключа ЗагрузкаФичПриОткрытии дополнительно записывается напрямую в реквизит (если элемент формы доступен или его нет в форме), как это делает пользователь; чтобы значение действовало при следующем открытии, сохраните настройки VA. Предупреждение также возвращается для requires_restart. КаталогФич — READ_ONLY с подсказкой на open_feature_file/load_features/run_scenario; lifecycle-ключи — ACTION_ONLY; клиенты тестирования и GlobalVars — OUT_OF_SCOPE с подсказкой на профильные инструменты. apply по умолчанию сбрасывает CI-флаги (ЗакрытьTestClientПослеЗапускаСценариев, ЗавершитьРаботуСистемыПослеВыполненияВсехСценариев, ВыгружатьСтатусВыполненияСценариевВФайл), как UI; preserve_ci_flags=true сохраняет их, а set требует allow_ci_flags=true для явного изменения. Проверяются состояние сеанса (прогон, запись действий, загрузка фичи, самотестирование; для запуска из командной строки возвращается предупреждение, изменения разрешены) и expected_revision; expected_current_value поддерживается только для set. Если в наборе apply есть КаталогФич или lifecycle-ключ, он попадает в out_of_scope, остальной набор применяется. dry_run=true возвращает отчёт без изменения. Значения не маскируются. Формат ответа — format=markdown (по умолчанию) или json.
    manage_variables Чтение, установка и удаление переменных тестового контекста. Действия с переменными: get (по умолчанию), set, delete. Переменные позволяют хранить произвольные значения в памяти Vanessa Automation. Переменные бывают локальные и глобальные. Локальные существуют во время выполнения сценария; движок очищает их перед штатным запуском сценария. При выполнении одного шага и запуске с текущего шага контекст может сохраняться. Глобальные переменные существуют пока работает Vanessa Automation и не удаляются перед выполнением сценария. Если переменная не найдена, get и delete сообщают об этом в ответе. Для set параметр value обязателен; пустая строка — допустимое значение. Параметр is_global для get с указанным name и для delete определяет, какой контекст использовать; get без name показывает оба контекста.
    open_feature_file Открывает .feature файл в Vanessa Editor или активирует уже открытую вкладку; файл перечитывается с диска. Параметр filePath необязателен: если он не указан, перезагружается файл активной редактируемой вкладки (для memory-вкладки или пустой новой вкладки вернётся ошибка). Принимается только файл с расширением .feature (каталог не принимается). Используйте перед check_syntax, execute_feature_step и ручной навигацией по редактору.
    restart_vanessa Перезапускает Vanessa Automation из EPF, пересобранного на диске. Используйте, когда EPF обновлён, а в менеджере тестирования всё ещё работает старая запущенная копия. Инструмент сразу отвечает, что перезапуск начат; новая VA открывается после фактического закрытия старой формы — обычно в течение 30–60 секунд. Если старая форма не закроется за 120 секунд, перезапуск отменяется, а вторая VA не открывается (причина пишется в журнал регистрации). Текущая форма закрывается без подтверждения, несохранённые изменения редактора теряются; после перезапуска клиент тестирования нужно подключить заново. Регистрируется при установленном и активном расширении VAExtension в базе менеджера тестирования; для работы в расширении должна быть обработка VAExtension_ПерезапускVA. Ожидание фактического закрытия работает в VAExtension 1.44 или выше; с более старым расширением действует прежняя схема. Без расширения инструмента нет в списке. Работает для Vanessa Automation и Vanessa Automation Single, открытых из файла .epf.
    run_scenario Запускает выполнение сценариев. Отправляет прогресс по каждому шагу (step N/M). Возвращает итоговый результат после завершения (при wait=true). Если указан filePath — загрузит фичу, откроет в редакторе и запустит. Режимы: all (по умолчанию — все сценарии; если просят выполнить все сценарии, используйте режим all), reloadAndRun (перечитать файл с диска и выполнить все его сценарии с начала), selected (выбранный в редакторе, перед этим надо вызвать select_scenario), fromCurrentStep (с текущего шага, перед этим нужно вызвать select_step), reloadAndRunFromLine (перечитать файл с диска и выполнить сценарий со строки lineNumber; параметр обязателен). В режимах reloadAndRun и reloadAndRunFromLine фича перечитывается с диска; точки останова не переносятся, так как номера строк могли измениться. filePath — только файл .feature, каталог не принимается. При wait=false в ответе возвращается идентификатор прогона (runId); он же доступен в get_vanessa_automation_state и get_test_results. Перед запуском проверяется, что дерево фич построено для активной вкладки; при несоответствии возвращается ACTION_FAILED — загрузите фичу через open_feature_file или check_syntax. Проверка выполняется при включённой настройке ИспользоватьРедакторVanessaEditor.
    save_table_document_to_file Сохраняет содержимое табличного документа в файл на диске. Поддерживаемые форматы: mxl (MXL), xlsx (Excel), pdf (PDF). Параметр file_name обязателен и должен содержать полный путь к файлу. Параметр format необязательный, по умолчанию mxl. Параметр form_element_name обязателен и должен содержать имя элемента формы (табличного документа) для сохранения.
    search_for_steps_by_keywords Ищет шаги Vanessa Automation по переданной строке поиска и возвращает их в формате Markdown. Поиск производится по: представлению шагов, описании шагов и типу шагов. В любой параметр можно передавать несколько значений, разделенных вертикальной чертой |. Пример поиска шагов в представлении которых встречается слово "кнопка": search_name = "кнопка|кнопки|кнопку". Пример исключения шагов в представлении которых встречается слово "поле": exclude_name = "поле|поля". Пример поиска шагов в описании которых встречается слово "клиент тестирования": search_description = "клиент тестирования". Пример исключения шагов в описании которых встречается слово "гиперссылка": exclude_description = "гиперссылка|гиперссылки". Пример поиска шагов в типе которых встречается строка "Объекты конфигурации": search_type = "Объекты конфигурации". Пример исключения шагов в описании которых встречается строка "Переменные среды": exclude_type = "Переменные среды".
    select_scenario Делает сценарий текущим по его имени. Требует, чтобы дерево фич было построено для активной вкладки; при несоответствии возвращает ACTION_FAILED с просьбой загрузить фичу активной вкладки через open_feature_file или check_syntax. Если сценарий с таким именем есть только в другом файле дерева-каталога, возвращает ACTION_FAILED с указанием файла.
    select_step Делает шаг текущим по номеру строки. Для структуры сценария допускаются строки примеров, строка «Примеры:» и заголовок таблицы примеров. Требует, чтобы дерево фич было построено для активной вкладки; при несоответствии возвращает ACTION_FAILED с просьбой загрузить фичу активной вкладки через open_feature_file или check_syntax.
    speak_text Синтезирует переданный текст в речь и произносит его пользователю настроенным движком синтеза речи (настройки берутся с закладки "Сервис" - "Автоинструкции" - "Аудио" - "Озвучивание диктором"). Параметр text обязателен и является массивом строк: при no_play=false массив должен содержать ровно одну фразу, при no_play=true - до 100 фраз (до 10 фраз синтезируются синхронно, больше 10 - пакетно с отправкой прогресса). Каждый элемент - до 500 символов; суммарная длина при синхронном синтезе - до 5000 символов, в пакете - до 50000. Полезно, чтобы голосом сообщить пользователю о завершении длинного задания, о необходимости принять решение или об ошибке. Во время воспроизведения другие MCP-инструменты доступны: плеер работает в отдельном потоке; ошибку возвращает только повторный speak_text, пока предыдущая фраза звучит. Синтез новой фразы синхронный и блокирует интерфейс Vanessa Automation, поэтому во время синтеза другие вызовы ждут. Параметр wait (boolean, по умолчанию false): если true, ответ возвращается после окончания воспроизведения фразы; действует только при no_play=false, при no_play=true игнорируется. Параметр no_play (boolean, по умолчанию false): если true, текст только синтезируется и сохраняется в кеш озвучки, без воспроизведения - полезно для прогрева кеша, последующий вызов с тем же текстом возьмёт озвучку из кеша без обращения к сервису синтеза. Прогрев требует включённого кеширования озвучки в настройках (Сервис - Автоинструкции - Аудио); в режиме обучения прогрев не работает. В режиме no_play при 10 и менее фразах ответ возвращается синхронно после завершения синтеза и может занять несколько секунд; при 11-100 фразах синтез идёт пакетно, ответ приходит после последней фразы, а при наличии токена прогресса отправляются уведомления. Ограничение "пока фраза звучит, повторный вызов возвращает ошибку" на no_play не действует. Требует включённую внешнюю компоненту VanessaExt. Не работает в веб-клиенте и под Linux.
    stop_scenario Посылает команду Vanessa Automation, что нужно остановить выполнение сценариев. На обработку команды может понадобится время. При отсутствии активного прогона сообщает, что останавливать нечего. Ошибка команды остановки возвращается как ACTION_FAILED.
    user_actions_recording Управляет записью действий пользователя в клиенте тестирования. Поддерживаемые действия (параметр action): start (по умолчанию) - начать запись действий пользователя (если запись уже идёт, новая не начинается и текущая не останавливается), stop - остановить запись и вернуть записанные шаги в формате Turbo Gherkin (если запись уже завершена, повторная остановка не выполняется и возвращается последний сохранённый результат), status - состояние записи и последнего результата (идёт ли запись, есть ли завершённый результат, идентификатор захвата, время завершения, длина текста), get_result - вернуть последний завершённый результат записи, не изменяя его и не останавливая новую запись, clear - очистить сохранённый результат записи. Необязательный параметр capture_id задаёт идентификатор захвата для get_result и clear; если он не совпадает с актуальным, get_result возвращает только метаданные актуального результата (без текста), а clear ничего не очищает. Результат записи сохраняется при любой остановке: кнопкой Vanessa, из MCP или шагом библиотеки. Сохранённый результат живёт до закрытия формы Vanessa Automation. Действия status, get_result, clear и stop при уже завершённой записи не требуют подключённого клиента тестирования. Инструмент не изменяет открытый в редакторе feature-файл.
    voice_notification Воспроизводит голосовое уведомление через внешнюю компоненту VanessaExt. Полезно в тех случаях, если ИИ агент работает в отдельной виртуальной машине, выполняет какое-то длинное задание и пользователю удобно получать голосовое уведомление о: задании выполненном, необходимости принять решение, задании, которое не может быть выполнено, или ошибке при выполнении задания.
    window_management Универсальный инструмент для управления окнами клиента тестирования. Поддерживаемые действия (параметр action): activate - активизировать окно по заголовку (требуется window_title), close - закрыть окно по заголовку (требуется window_title; для поиска по части заголовка используйте маску , например 'Окно'), open_navigation - открыть навигационную ссылку (требуется navigation_link). Для активизации окна: укажите action='activate' и window_title с полным заголовком окна или используйте символы * для поиска по частичному совпадению (например, 'Окно'). Без маски заголовок сравнивается целиком. Для закрытия окна: укажите action='close' и window_title с полным заголовком окна или используйте символы * для поиска по частичному совпадению (например, 'Окно*'). Без маски заголовок сравнивается целиком. Для открытия формы: укажите action='openavigation' и **vigationink** с вигационной ссылкой; если такая форма уже открыта, открывается новое окно - переключитесь на нужное окно действием active**, дубликаты закрывайте действием close.
