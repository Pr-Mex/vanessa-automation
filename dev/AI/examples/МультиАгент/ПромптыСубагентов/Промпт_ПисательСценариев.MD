> **Назначение:** готовый промпт для запуска субагента Писателя через инструмент `Agent`. Перед запуском Управляющий Агент ОБЯЗАН подставить конкретный номер сценария `<NN>` и имя сценария в выделенные места.

---

## Текст промпта

```
Надо написать тест для конфигурации **<ИмяКонфигурации>** (см. `Параметры конфигурации`), которая подключена как клиент тестирования, и ОБЯЗАТЕЛЬНО запустить сценарий в этом клиенте, чтобы он выполнялся без ошибок.

## 📋 Контекст сценария

Перед началом работы прочитай `ТестПлан.MD` — найди блок `## Тест <NN>: <КраткоеНазвание>` с твоим сценарием. Блоки `**Дано:**` / `**Когда:**` / `**Тогда:**` дадут верхнеуровневое представление о сценарии (что проверяем, какие условия, какой результат).

## 🚨 КРИТИЧНО: ОБЯЗАТЕЛЬНЫЙ ЦИКЛ ОТЛАДКИ

Твоя задача НЕ выполнена, пока сценарий не запустится без ошибок через `run_scenario`.
Ты должен выполнить следующие шаги в строгом порядке:

1. Прочитай `data/АнализДанных_<NN>_<КраткоеНазвание>.MD` (подготовлено субагентом АнализДанныхИИнтерфейса).
2. Прочитай `research/РезультатИсследования_<NN>_<КраткоеНазвание>.MD` (подготовлено субагентом Исследователем).
3. Прочитай `InstructionsWriteScenario.md` и образцы в `features/*.feature`.
4. Напиши черновик `features/<NN>_<КраткоеНазвание>.feature`.
5. Открой файл в Vanessa Automation: `open_feature_file(filePath=...)`.
6. Проверь синтаксис: `check_syntax(filePath=...)`. Если ошибки — исправь и повтори.
7. Запусти сценарий: `run_scenario(filePath=..., mode=all)`.
8. Получи результаты: `get_test_results()`.
9. Проверь, что ВСЕ шаги имеют статус «Success», НЕТ ни одного «Failed» и НЕТ ни одного «Pending».
10. Если есть упавшие или пропущенные шаги — проанализируй ошибки, исправь feature файл, вернись к шагу 7.
11. Повторяй шаги 7-10 пока `get_test_results` не покажет все шаги успешными (Failed = 0, Pending = 0, Success = N).
12. Когда все шаги успешны — зафиксируй итоговое количество итераций и затраченное время в начале feature файла в виде комментария:
    `# DEBUG: <N> итераций, <время> сек, последний успешный запуск <YYYY-MM-DD HH:MM:SS>`

ЗАПРЕЩЕНО сообщать Управляющему Агенту о завершении работы, если `get_test_results` показывает упавшие или Pending-шаги.

До тебя работал исследователь и он составил Требования к тесту в файле `research/РезультатИсследования_<NN>_<КраткоеНазвание>.MD`.
Также до Исследователя работал субагент АнализДанныхИИнтерфейса, который подготовил файл `data/АнализДанных_<NN>_<КраткоеНазвание>.MD` с командным интерфейсом и рекомендациями по данным — обязательно прочитай его.
Тебе надо написать сценарий в виде feature файла, строго следуя инструкциям из файла InstructionsWriteScenario.md.

## 📚 Существующие feature файлы
В каталоге `features/` уже есть feature файлы, которые прошли код-ревью.
Прочитай их в начале работы и ориентируйся на них при создании своего сценария
(стиль оформления, используемые шаги, структура сценария).
**Не путай каталог `features/` (для feature файлов) с каталогом `png/` (для скриншотов) в корне проекта.**

## 📄 Имя feature файла
В имени feature файла обязательно укажи номер сценария, например:
`features/<NN>_<КраткоеНазвание>.feature`

## 📸 Скриншоты
Если в процессе отладки ты создаёшь скриншоты (через инструменты Vanessa Automation),
сохраняй их в каталог `png/` в корне проекта (НЕ в `features/`).
Пример имени скриншота: `png/<NN>_<краткое_описание>.png`.

## 📝 Лог работы (ОБЯЗАТЕЛЬНО)

Ты ОБЯЗАН вести подробный лог своей работы в файле:
`writer/ПисательСценариев_<NN>_<КраткоеНазвание>.MD`

**Создай каталог `writer/`** в начале работы (`mkdir -p writer`).
**Создай файл лога** сразу после прочтения файлов исследования
и **обновляй его на КАЖДОЙ итерации** отладки и после **КАЖДОГО вызова инструмента**.

### Что записывать в лог

1. **Дата и время начала работы**
2. **Прочитанные входные файлы** (с полными путями)
3. **Созданные/изменённые файлы** (feature файл, скриншоты, лог)
4. **🔧 История вызовов инструментов** — КАЖДЫЙ вызов инструмента
   Vanessa Automation (`mcp__VA__*`) с фиксацией:
   - Время вызова
   - Имя инструмента (например, `run_scenario`, `check_syntax`)
   - Ключевые параметры (без полного вывода)
   - Краткий результат (✅ Success / ❌ Error с кратким описанием)
5. **Для каждой итерации запуска**:
   - Номер итерации
   - Время начала и окончания итерации
   - Какие изменения внесены в feature файл
   - Результат `get_test_results` (количество Success / Failed / Pending)
   - Текст ошибок упавших шагов (если были)
   - Скриншоты упавших шагов (если есть)
6. **📊 Оценка полезности инструментов** — после завершения работы:
   - Какие инструменты были использованы
   - Какие оказались наиболее полезны и почему
   - Какие были бесполезны или избыточны
   - Рекомендации для будущих сценариев
7. **⚠️ Проблемы и решения** — детальный отчёт:
   - С какими трудностями столкнулся Писатель
   - Какие ошибки были НЕ связаны с feature файлом
   - Как решались (или НЕ решились) проблемы
   - Сколько времени заняло решение
8. **Финальный результат**:
   - Общее количество итераций
   - Общее время работы
   - Финальный статус (✅ УСПЕХ / ❌ DEBUG_FAILED)
   - Имя созданного feature файла

### Когда записывать

| Событие | Что писать в лог |
|---------|------------------|
| Начало работы | Создать файл лога с шапкой и разделом «📥 Входные данные» |
| Прочтение входного файла | Запись в раздел «📥 Входные данные» |
| **Каждый вызов инструмента** | **Строка в таблице «🔧 История вызовов инструментов»** |
| Каждая итерация запуска | Новый блок «### Итерация N» |
| Изменение feature файла | Описание внесённых изменений |
| Упавший шаг | Текст ошибки + путь к скриншоту |
| **Обнаружение проблемы** | **Новый блок в разделе «⚠️ Проблемы и решения»** |
| **Решение проблемы** | **Обновить блок проблемы, указав решение** |
| **Завершение работы** | **Заполнить разделы «📊 Оценка полезности», «⚠️ Проблемы», «📊 Итоговая статистика»** |

### КРИТИЧНО

Без заполненного лога (включая все 3 обязательных раздела:
«🔧 История вызовов инструментов», «📊 Оценка полезности»,
«⚠️ Проблемы и решения») работа Писателя считается **НЕ ЗАВЕРШЁННОЙ**.

Управляющий Агент ОБЯЗАН перед принятием результата проверить:
1. ✅ Файл лога существует в `writer/`
2. ✅ Все 3 раздела заполнены
3. ✅ Количество вызовов инструментов > 0
4. ✅ Есть оценка полезности хотя бы 3 инструментов
5. ✅ Зафиксированы все обнаруженные проблемы
```

## Параметры запуска Управляющим Агентом

- `subagent_type`: `"general-purpose"` (обязательно, т.к. нужны `mcp__VA__*` инструменты для отладки через `run_scenario`)
- `prompt`: текст из секции «Текст промпта» выше (без обрамляющих ```)
- После `<NN>` и `<КраткоеНазвание>` подставить реальные значения из `ТестПлан.MD`.
- Если используется fallback `subagent_type="Explore"` — добавить блок «⚠️ Ограничение инструментов» (см. основной файл `ПодготовкаУправляющегоАгента.MD`).
