# MCP в Vanessa Automation

## Быстрый старт

Для начала использования MCP в Vanessa Automation выполните следующие шаги:

1. **Настройте LLM с поддержкой MCP**. У вас должна быть работающая LLM, к которой можно подключить MCP инструменты. Например, VSCode + плагин Cline — это среда, где вы пишете промты.

2. **Установите расширение в базу менеджера тестирования**. В базу менеджера тестирования необходимо поставить расширение из [проекта](https://github.com/1c-neurofish/onec-client-mcp-devkit/releases).

3. **Запустите MCP сервер**. Нажмите на кнопку **Запустить** в расширении.

4. **Настройте MCP клиент в вашей IDE**. В вашей IDE, где работает LLM, необходимо прописать настройки MCP сервера, который запущен в менеджере тестирования. В инструкции ниже приведены примеры настроек для плагина Continue (для VSCode), плагина Cline и плагина Roo Code (тоже для VSCode).

5. **Включите внешнюю компоненту VanessaExt**. В Vanessa Automation необходимо включить использование внешней компоненты VanessaExt.

6. **Установите расширение VAExtension**. В базу клиента тестирования необходимо добавить расширение VAExtension.

7. **Настройка завершена**. После выполнения всех шагов MCP готов к работе.

## 🚀 Реальный проект покрытия тестами

Файлы из `examples/МультиАгент/` — это **шаблоны**. Для покрытия тестами конкретной конфигурации 1С создаётся **реальный проект** — отдельный каталог, в котором лежат копии шаблонов и проектные данные.

### 📂 Структура реального проекта

```
<корень_проекта>/
├── ТестПлан.MD                  ← Вход: тесты в свободной форме (Дано/Когда/Тогда)
├── ТестПлан.pdf                 ← PDF-версия для согласования (опционально)
├── ПараметрыКонфигурации.MD     ← Пути к DT, исходникам, профилю (ОБЯЗАТЕЛЬНО)
│
├── InstructionsResearch.md       ← Копия шаблона
├── InstructionsWriteScenario.md ← Копия шаблона
├── ПодготовкаУправляющегоАгента.MD ← Копия шаблона
│
├── ПромптыСубагентов/           ← Копии промптов субагентов
│
├── Чеклисты/                    ← Чек-листы для ревьюеров
│   └── *.MD
│
├── dt/                          ← DT-эталон и лог restore
│   ├── <Эталон>.dt
│   └── log.txt
│
├── data/                        ← Выход: анализ командного интерфейса
│   └── АнализДанных_<NN>_<...>.MD
│
├── research/                    ← Выход: результаты исследования
│   └── РезультатИсследования_<NN>_<...>.MD
│
├── features/                    ← Выход: готовые feature-файлы
│   └── <NN>_<КраткоеНазвание>.feature
│
├── rewiew/                      ← Выход: отчёты ревьюеров
│   ├── rewiew_<NN>_<...>_Researcher_<N>.MD
│   └── rewiew_<NN>_<...>_Writer_<N>.MD
│
├── restore/                     ← Выход: отчёты о восстановлении базы
│   └── Restore_<NN>_<...>.MD
│
├── writer/                      ← Выход: логи работы Писателя
│   └── ПисательСценариев_<NN>_<...>.MD
│
├── png/                         ← Скриншоты (создаются при отладке)
│
└── Архив/                       ← Старые/неактуальные файлы
```

### 🔄 Полный workflow от ТестПлан.MD до готовых feature-файлов

```
ВХОДЫ (пользователь):
├── ТестПлан.MD           — тесты в свободной форме
├── dt/<Эталон>.dt        — эталонное состояние базы
└── ПараметрыКонфигурации.MD — пути проекта

         ↓

УПРАВЛЯЮЩИЙ АГЕНТ (оркестратор):
1. Парсит ТестПлан.MD → СПИСОК_СЦЕНАРИЕВ
2. Для каждого сценария запускает цепочку субагентов

         ↓

ВЫХОДЫ (по каждому сценарию):
├── data/АнализДанных_<NN>.MD            ← от АнализДанныхИИнтерфейса
├── research/РезультатИсследования_<NN>.MD ← от Исследователя
├── rewiew/rewiew_<NN>_Researcher.md     ← от Код-Ревьюера (Researcher)
├── features/<NN>_<...>.feature         ← от Писателя
├── rewiew/rewiew_<NN>_Writer.md         ← от Код-Ревьюера (Writer)
├── restore/Restore_<NN>.MD             ← от АдминистраторБазы
└── writer/ПисательСценариев_<NN>.MD    ← лог работы Писателя

         ↓

НАКОПЛЕНИЕ ЗНАНИЙ:
└── Memory.MD  ← по итогам работы сюда записываются
                  новые знания о конфигурации
```

### 📋 Шаги для запуска нового тестового проекта

1. **Создать каталог проекта** (например, `C:\Commons\rep\AI\testERP7\`).
2. **Скопировать шаблоны** из `examples/МультиАгент/`:
   - `InstructionsResearch.md`
   - `InstructionsWriteScenario.md`
   - `ПодготовкаУправляющегоАгента.MD`
   - `ПромптыСубагентов/` (целиком)
3. **Создать `ПараметрыКонфигурации.MD`** и заполнить пути.
4. **Подготовить DT-эталон** — положить в `dt/<Эталон>.dt`.
5. **Написать `ТестПлан.MD`** — заполнить тесты в свободной форме.
6. **Запустить Управляющего Агента** (см. `ПодготовкаУправляющегоАгента.MD`).

### 🔗 Связь между шаблонами и реальным проектом

| Шаблон (`examples/МультиАгент/`) | Копия в реальном проекте | Отличия |
|----------------------------------|--------------------------|---------|
| `ПодготовкаУправляющегоАгента.MD` | копируется | обычно без изменений |
| `InstructionsResearch.md` | копируется | может дополняться под конфигурацию |
| `InstructionsWriteScenario.md` | копируется | обычно без изменений |
| `ПромптыСубагентов/*.MD` | копируются в `ПромптыСубагентов/` | обычно без изменений |
| `ПараметрыКонфигурации.MD` (шаблон) | **создаётся** в проекте | заполняется конкретными путями |
| `ТестПлан.MD` (шаблон) | **создаётся** в проекте | заполняется тестами |
| — | `dt/`, `data/`, `features/` и т.п. | создаются автоматически |

### ⚠️ Что НЕ нужно менять

- Шаблоны промптов **уже универсальны** — они читают `ПараметрыКонфигурации.MD` и `ТестПлан.MD` из текущего каталога проекта.
- `ПодготовкаУправляющегоАгента.MD` универсален — он парсит `ТестПлан.MD` и запускает субагентов.
- `Memory.MD` пуст при старте и наполняется по ходу работы.

## 🤖 Многоагентный режим покрытия тестами

Для сложных задач используется **многоагентная система**, описанная в
[`examples/МультиАгент/ПодготовкаУправляющегоАгента.MD`](examples/МультиАгент/ПодготовкаУправляющегоАгента.MD).

### Цепочка субагентов для каждого сценария

```
[Пользователь] → ТестПлан.MD
        ↓
Управляющий Агент (парсит ТестПлан, итерирует по сценариям)
        ↓
1. АнализДанныхИИнтерфейса → data/АнализДанных_<NN>.MD
        ↓
2. Исследователь → research/РезультатИсследования_<NN>.MD
        ↓
3. Код-Ревьюер (Researcher) → rewiew/rewiew_<NN>_Researcher.md
        ↓ (если ✅)
4. Писатель → features/<NN>_<...>.feature
        ↓
5. Код-Ревьюер (Writer) → rewiew/rewiew_<NN>_Writer.md
        ↓ (если ✅)
6. ✅ Готово!
        ↓ (следующий сценарий)
7. АдминистраторБазы → restore/Restore_<NN>.MD
```

## 🔗 Рекомендуемый порядок работы с файлами

### Для простого случая (1-2 сценария)

```
ТестПлан.MD (ввод теста в свободной форме)
        ↓
InstructionsResearch.md →  Исследование через UI клиента тестирования
        ↓
InstructionsWriteScenario.md →  Написание и отладка feature-файла
```

### Для сложного случая (многоагентный режим)

```
ПараметрыКонфигурации.MD → Заполнить пути проекта
        ↓
ТестПлан.MD → Описать все тесты в свободной форме
        ↓
ПодготовкаУправляющегоАгента.MD → Запустить оркестратор
        ↓
   (для каждого теста автоматически:)
   АнализДанныхИИнтерфейса → Исследователь → Код-Ревьюер →
   Писатель → Код-Ревьюер → ✅ Готово
        ↓
features/*.feature, research/*.MD, rewiew/*.MD, restore/*.MD
```

## Доступные инструменты:

Ниже приведена таблица всех доступных MCP инструментов Vanessa Automation, отсортированная по имени инструмента.

| Инструмент | Описание |
|------------|----------|
| **check_syntax** | Проверяет синтаксис Gherkin в указанном feature-файле. Параметр **filePath** обязателен. Возвращает Markdown с найденными ошибками: неизвестные шаги, структурные проблемы, ошибки ключевых слов. |
| **close_test_client** | Закрывает сеанс клиента тестирования по имени профиля. Если профиль не указан — закрывает текущий подключенный профиль. Используйте для завершения работы с клиентом тестирования после выполнения тестов. |
| **execute_feature_step** | Выполняет шаг из .feature файла по номеру строки. Валидирует что файл открыт в редакторе, активирует вкладку при необходимости. |
| **execute_form_actions** | Выполняет последовательность действий с элементами формы клиента тестирования. Позволяет выполнить несколько действий за один вызов инструмента. Параметр **actions_json** (обязательный) - JSON-строка с массивом действий. Каждое действие в массиве содержит: **action** - тип действия (click_button, input_text, и т.д.), **element_name** - имя элемента формы, **table_name** - имя таблицы (если элемент в таблице), **value** - значение для ввода/выбора, другие параметры в зависимости от действия. При возникновении ошибки выполнение прерывается. Требует подключённого клиента тестирования. |
| **frequently_used_steps** | Возвращает информацию о том какие шаги чаще используются по статистике больших проектов. В начале идут часто используемые шаги, далее идут более редко используемые шаги. Возвращает представление шага, описание шага, тип шага. Также возвращает информацию сколько всего шагов есть в накопленной статистике. |
| **get_active_window_data** | В зависимости от параметра **type** возвращает важные свойства активного окна клиента тестирования: если type=**window_caption** - возвращает самое важное значение активного окна: его заголовок. По заголовку окна можно найти окно и получить его данные, можно активизировать окно, можно закрыть окно. Если type=**navigation_link** - возвращает навигационную ссылку активного окна. | **voice_notification** | Воспроизводит голосовое уведомление через внешнюю компоненту VanessaExt. Полезно в тех случаях, если ИИ агент работает в отдельной виртуальной машине, выполняет какое-то длинное задание и пользователю удобно получать голосовое уведомление о: задании выполненном, необходимости принять решение, задании, которое не может быть выполнено, или ошибке при выполнении задания. |
| **window_management** | Универсальный инструмент для управления окнами клиента тестирования. Поддерживаемые действия (параметр **action**): **activate** - активизировать окно по заголовку (требуется **window_title**), **close** - закрыть окно по заголовку или части заголовка (требуется **window_title**), **open_navigation** - открыть навигационную ссылку (требуется **navigation_link**). Для активизации окна: укажите **action**='activate' и **window_title** с полным заголовком окна или используйте символы * для поиска по частичному совпадению (например, '*Окно*'). Для закрытия окна: укажите **action**='close' и **window_title** (можно часть заголовка для поиска или используйте символы * для поиска по частичному совпадению). Для открытия формы: укажите **action**='open_navigation' и **navigation_link** с навигационной ссылкой. |
