# Техническое задание: MCP-сервер для Vanessa Automation

## Полная спецификация реализации по фазам

**Версия:** 1.0  
**Дата:** 2026-03-18  
**Ветка:** mcp  
**MCP Protocol:** 2025-03-26 (Streamable HTTP)  
**Файл реализации:** `VanessaAutomation/Forms/УправляемаяФорма/Ext/Form/Module.bsl`  
**DLL-транспорт:** `http1c` v1.3.0 (проект MCP-DB-Client)

---

## Архитектура

```
AI (VS Code / Copilot)  ←→  MCP Server (http1c DLL)  ←→  Vanessa Automation (BSL)
                              │                              ├─ Monaco Editor (VanessaTabs)
                              │                              ├─ Test Runner
                              │                              ├─ Step Library
                              │                              ├─ TestClient (1С)
                              │                              └─ Form Inspector
                              │
                              ├─ POST /mcp  — JSON-RPC запросы
                              ├─ GET  /mcp  — SSE-уведомления
                              └─ DELETE /mcp — завершение сессии
```

### Протокол взаимодействия DLL ↔ BSL

- **Регистрация инструментов:** `MCPКомпонента.Инструменты = JSONСтрока` (write-only свойство)
- **Регистрация ресурсов:** `MCPКомпонента.Ресурсы = JSONСтрока` (write-only свойство)
- **Регистрация промптов:** `MCPКомпонента.Промпты = JSONСтрока` (write-only свойство)
- **Входящие события:** `ВнешнееСобытие("HttpServer", "ToolCall"|"ResourceRead"|"PromptGet", JSONДанные)`
- **Отправка ответа:** `MCPКомпонента.НачатьВызовОтправитьОтвет(callback, JSON{"id", "body"})`
- **Отправка прогресса:** `MCPКомпонента.НачатьВызовОтправитьПрогресс(callback, requestId, progress, total, message)`

### Формат событий от DLL

- **ToolCall:** `{"id": "req_...", "tool": "toolName", "arguments": {...}, "progressToken": "..."}`
- **ResourceRead:** `{"id": "req_...", "type": "resource_read", "uri": "va://state"}`
- **PromptGet:** `{"id": "req_...", "type": "prompt_get", "name": "...", "arguments": {...}}`

### Формат ответов в DLL

- **Инструменты:** `{"id": "...", "body": "{\"content\": [...]}"}` — DLL проверяет ключ `"content"`
- **Ресурсы:** `{"id": "...", "body": "{\"contents\": [...]}"}` — DLL проверяет ключ `"contents"`
- **Промпты:** `{"id": "...", "body": "{\"messages\": [...]}"}` — DLL проверяет ключ `"messages"`

---

## Принципы реализации

1. **Markdown** — все текстовые ответы инструментов форматируются как Markdown
2. **Все процедуры `&НаКлиенте`** — кроме серверных функций получения данных
3. **Async-паттерн** — `НачатьВызов*` + `ОписаниеОповещения` для вызовов компоненты
4. **Try/Except** — все обработчики оборачивают бизнес-логику в Попытка/Исключение
5. **Progress** — долгие операции (runScenario) отправляют прогресс через `MCPОтправитьПрогресс`
6. **Модульные переменные** для отслеживания состояния:
   - `MCPТекущийProgressToken` — токен прогресса из текущего запроса
   - `MCPТекущийИдентификаторЗапроса` — ID текущего запроса
   - `MCPОжиданиеВыполненияСценария` — флаг ожидания завершения сценария
   - `MCPИдентификаторЗапросаСценария` — ID запроса запуска сценария

3. Отправляет `MCPОтправитьПрогресс(id, completedSteps, totalSteps, "Шаг N/M: stepName")`
4. По завершении вызывает `MCPОтправитьРезультатСценария(id)`
