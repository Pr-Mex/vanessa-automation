# Vanessa Automation MCP — Инструкция для ИИ-агента

Ты подключён к MCP-серверу Vanessa Automation — фреймворку для BDD-тестирования приложений 1С:Предприятие. Через MCP-инструменты ты можешь управлять тестовым клиентом, выполнять шаги Gherkin, писать и запускать сценарии, анализировать формы и делать скриншоты.

## Архитектура

```
Ты (ИИ) ←MCP→ DLL (http1c) ←→ Vanessa Automation (1С) ←→ Тестируемое приложение 1С
```

- Vanessa Automation (VA) — обработка в режиме "Предприятие", открытая в 1С
- Тестовое приложение — отдельный экземпляр 1С, которым управляет VA через TestManager
- MCP-сервер — DLL-компонента внутри VA, обрабатывает JSON-RPC запросы

## Порядок работы (обязательный)

### 1. Узнай состояние

```
getVAState → текущее состояние VA, подключён ли клиент тестирования
getCurrentDate → дата и время на сервере 1С
```

### 2. Подключи клиент тестирования

```
connectTestClient(profileName="Этот клиент")
```

**Без подключённого клиента тестирования шаги executeStep не будут работать!**

Если не знаешь имя профиля — вызови `getVAState`, в ответе будет список доступных профилей.

### 3. Исследуй текущую форму

```
getFormAnalysis(format="elements") → дерево элементов с их именами
getFormAnalysis(format="gherkin") → значения полей в формате Gherkin
takeScreenshot() → скриншот текущего состояния
```

### 4. Выполняй шаги

```
executeStep(stepText="И я нажимаю на кнопку с именем 'ИмяКнопки'")
executeFeatureStep(filePath="C:\\Tests\\login.feature", lineNumber=15) → выполнить шаг из файла по номеру строки
```

`executeFeatureStep` автоматически открывает/активирует вкладку файла в редакторе, читает текст указанной строки и выполняет его как шаг. Используй, когда нужно выполнить конкретный шаг из известного файла.

### 5. Ищи шаги

```
searchSteps(query="И я нажимаю на кнопку с именем 'ФормаЗаписать'") → точный поиск по полному тексту
searchSteps(query="Первая фраза|Вторая фраза") → точный поиск любой из альтернатив
```

`searchSteps` не использует семантический поиск. Он ищет только точные текстовые совпадения без учета регистра. Если нужен поиск по нескольким вариантам, передай их в `query` через `|`.

### 6. Пиши и запускай сценарии

```
loadFeatures(path="путь/к/файлу.feature") → загрузить фичу в дерево
runScenario() → запустить все загруженные сценарии
runScenario(filePath="путь/к/файлу.feature") → загрузить и запустить за один вызов
```

## Ключевые особенности

### Шаги пишутся на русском языке

Все шаги Gherkin в VA — на русском. Примеры:

```gherkin
И я нажимаю на кнопку с именем 'Записать'
И в поле с именем 'Наименование' я ввожу текст 'Тестовый товар'
И элемент формы с именем 'КодТовара' присутствует на форме
Дано Я открываю навигационную ссылку 'e1cib/list/Справочник.Товары'
И я закрыл все окна клиентского приложения
```

### Имена элементов — из getFormAnalysis

Не угадывай имена кнопок и полей. Всегда сначала вызови `getFormAnalysis(format="elements")` чтобы увидеть точные имена. Имена элементов формы в 1С — программные идентификаторы (например `ФормаЗаписатьИЗакрыть`, не "Записать и закрыть").

### Навигация по приложению

Для перехода к нужному разделу используй навигационные ссылки:

```gherkin
Дано Я открываю навигационную ссылку 'e1cib/list/Справочник.Товары'
Дано Я открываю навигационную ссылку 'e1cib/list/Документ.РасходнаяНакладная'
```

### Закрывай окна перед навигацией

```gherkin
И я закрыл все окна клиентского приложения
```

Этот шаг закрывает все окна тестового приложения. Используй его перед навигацией к новому разделу, чтобы избежать конфликтов с модальными диалогами.

### executeStep возвращает статусы

- **Success** — шаг выполнен (время >100 мс — реальное действие)
- **Warning** — шаг завершился подозрительно быстро (<100 мс) — возможно не оказал эффекта
- **Error** — ошибка: текст ошибки в результате

### runScenario — полный цикл

`runScenario` запускает сценарии из загруженного дерева. Режимы:

- `all` (по умолчанию) — все загруженные сценарии
- `selected` — выделенный в дереве (требует ручного выбора)
- `reloadAndRun` — перезагрузить и запустить выделенный
- `fromCurrentStep` — с текущего шага

**Рекомендуемый способ**: `runScenario(filePath="путь/к/файлу.feature")` — загрузит фичу и запустит все сценарии за один вызов.

### Формат .feature файла

```gherkin
# language: ru

Функционал: Описание тестируемого функционала
  Как роль
  Я хочу действие
  Чтобы цель

  @тег
  Сценарий: Название сценария
    Дано предусловие
    Когда действие
    Тогда результат
    И ещё одна проверка
```

## Типичные рабочие сценарии

### Исследование приложения

```
1. getVAState                       → проверить состояние
2. connectTestClient("Этот клиент") → подключиться
3. getFormAnalysis(format="elements")→ увидеть элементы
4. takeScreenshot()                  → визуальное состояние
5. executeStep(stepText="И я нажимаю...")     → взаимодействие
```

### Создание записи в справочнике

```
1. connectTestClient("Этот клиент")
2. executeStep(stepText="И я закрыл все окна клиентского приложения")
3. executeStep(stepText="Дано Я открываю навигационную ссылку 'e1cib/list/Справочник.Товары'")
4. getFormAnalysis(format="elements") → найти кнопку создания
5. executeStep(stepText="И я нажимаю на кнопку с именем 'СписокСоздать'")  
6. getFormAnalysis(format="elements") → найти поля формы
7. executeStep(stepText="И в поле с именем 'Наименование' я ввожу текст 'Тестовый товар'")
8. executeStep(stepText="И я нажимаю на кнопку с именем 'ФормаЗаписатьИЗакрыть'")
```

### Написание и запуск BDD-теста

```
1. searchSteps(query="И я нажимаю на кнопку с именем 'ФормаЗаписать'|И я нажимаю кнопку 'Записать'") → найти нужный шаг по точному тексту или одной из альтернатив
2. Создать .feature файл с найденными шагами
3. runScenario(filePath="путь/к/файлу.feature") → запустить
4. Если Failed → analyzeFailedTest → исправить → повторить
```

### Анализ упавшего теста

```
1. runScenario(filePath="...") → Failed
2. Прочитать ошибку из результата (имя шага, описание ошибки, активная форма)
3. getFormAnalysis(format="elements") → реальные имена элементов
4. takeScreenshot() → визуальное состояние после ошибки
5. Исправить .feature файл → повторить runScenario
```

## Частые ошибки и как их избежать

| Ошибка | Причина | Решение |
|--------|---------|---------|
| "Нет активного .feature файла" | VanessaEditor не имеет открытой вкладки | Используй `filePath` в `runScenario` или `openFeatureFile` перед запуском |
| "Элемент не виден на текущей форме" | Элемент существует но не виден (свёрнут, за экраном) | Используй `getFormAnalysis(format="elements")` — там видна иерархия. Попробуй другой элемент |
| executeStep → Warning, <100ms | Шаг не нашёл что делать (возможно, форма не та) | Проверь текущую форму через `getFormAnalysis` |
| "Клиент тестирования не подключен" | Забыл `connectTestClient` | Вызови `connectTestClient` перед работой с формами |
| "Шаг не найден в библиотеке" | Неправильный синтаксис шага | Используй `searchSteps` чтобы найти точный текст шага. Помни, что это точный текстовый поиск без семантики, а альтернативы задаются через `|` |

## Работа с системными диалогами

При некоторых действиях 1С показывает модальные диалоги с вопросами. Ты должен на них отвечать:

```gherkin
# Удаление элемента — появится диалог "Пометить на удаление?"
И я нажимаю на кнопку с именем 'ФормаУстановитьПометкуУдаления'
И я нажимаю на кнопку 'Yes'

# Закрытие несохранённой формы — диалог "Данные были изменены. Сохранить?"
И я нажимаю на кнопку 'No'

# Проведение документа may ask for confirmation
И я нажимаю на кнопку 'OK'
```

**Важно**: текст кнопок в диалогах зависит от языка интерфейса приложения (English: `Yes/No/OK/Cancel`, Русский: `Да/Нет/ОК/Отмена`). Проверь язык через `getFormAnalysis` или `takeScreenshot`.

## Работа с таблицами

```gherkin
# Выбрать строку в таблице (двойной клик — открывает запись)
И в таблице 'Список' я выбираю текущую строку

# Перейти к конкретной строке  
И в таблице 'Список' я перехожу к строке с колонкой 'Наименование' равной 'Обувь'
```

## Отладка проблем

### Если шаг не находит элемент

1. `getFormAnalysis(format="elements")` — посмотри реальные имена элементов
2. Убедись, что активна нужная форма (в ответе видно `{Tested form}`)
3. Если элемент в свёрнутой группе — попробуй другой подход

### Если шаг выполняется, но ничего не происходит

1. `takeScreenshot()` — проверь визуальное состояние
2. `getFormAnalysis(format="gherkin")` — проверь значения полей
3. Возможно, шаг применился к другой форме — закрой лишние окна

### Если тестовый клиент отключился

1. `getVAState` → проверь `testClientConnected`
2. Если нет — `connectTestClient("Этот клиент")` заново

## MCP-ресурсы

Кроме инструментов, VA предоставляет MCP-ресурсы:

- `va://docs/quickstart` — краткое руководство по быстрому старту
- `va://docs/known-steps` — часто используемые шаги Gherkin с примерами

## Промпты

VA предоставляет MCP-промпты для типовых задач:

- `writeScenario(task="описание")` — генерация BDD-сценария с правильной структурой
- `analyzeFailedTest()` — анализ последнего упавшего теста с контекстом ошибки
