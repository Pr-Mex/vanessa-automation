# MCP-инструменты Vanessa Automation

Документ описывает MCP-инструменты, ресурсы и промпты, которые зарегистрированы в Vanessa Automation, а также поддерживаемые ими параметры.

## Общая схема

- Точка регистрации инструментов: `MCPЗарегистрироватьИнструменты()`
- Точка регистрации ресурсов: `MCPЗарегистрироватьРесурсы()`
- Точка регистрации промптов: `MCPЗарегистрироватьПромпты()`
- Диспетчер вызовов инструментов: `MCPОбработатьВызовИнструмента(Данные)`
- Диспетчер чтения ресурсов: `MCPОбработатьЧтениеРесурса(Данные)`
- Диспетчер получения промптов: `MCPОбработатьПолучениеПромпта(Данные)`
- Файл реализации: `VanessaAutomation/Forms/УправляемаяФорма/Ext/Form/Module.bsl`

### 3. `searchSteps`

- BSL-функция описания: `MCPИнструментSearchSteps()`
- BSL-обработчик верхнего уровня: `MCPОбработатьSearchSteps(ИдентификаторЗапроса, Аргументы)`
- Процедура выполнения поиска: `MCPВыполнитьПоискШаговИОтправитьРезультат(ИдентификаторЗапроса, Аргументы)`
- Назначение: найти доступные шаги Vanessa Automation и вернуть результат в Markdown.
- Аннотации: `readOnlyHint`, `idempotentHint`

Поддерживаемые параметры:

- `query: string`
  - необязательный параметр
  - подстрока для поиска по шагам
- `category: string`
  - необязательный параметр
  - фильтр по категории шага
- `searchScope: string`
  - необязательный параметр
  - область поиска
  - `name` — искать только по названию шага
  - `all` — искать по названию, описанию и строке поиска
  - по умолчанию используется `all`
- `limit: number`
  - необязательный параметр
  - максимальное количество элементов в выдаче
  - `0` означает вернуть все результаты
  - отрицательные значения недопустимы
  - по умолчанию используется `50`

Особенности работы:

- если `ТаблицаИзвестныхStepDefinition` пуста, инструмент запускает стандартную цепочку загрузки известных шагов
- после завершения асинхронной загрузки ответ возвращается в тот же MCP-запрос
- MCP-клиенту не нужно отдельно открывать форму известных шагов

Формат ответа:

- Markdown
- в начале выводятся:
  - поисковый запрос
  - категория
  - область поиска
  - лимит
  - общее количество найденных шагов
  - количество показанных шагов
  - список категорий
- далее выводится список шагов, для каждого шага показываются:
  - категория
  - описание
  - сниппет
  - строка поиска
  - исходный файл

Пример вызова:

```json
{
  "query": "аллюр",
  "category": "Прочее.Allure",
  "searchScope": "all",
  "limit": 10
}
```

### 4. `checkSyntax`

- BSL-функция описания: `MCPИнструментCheckSyntax()`
- BSL-обработчик: `MCPОбработатьCheckSyntax(ИдентификаторЗапроса, Аргументы)`
- Назначение: проверить синтаксис Gherkin в текущем документе редактора Vanessa Automation или в указанном `.feature` файле.
- Аннотации: `readOnlyHint`

Поддерживаемые параметры:

- `filePath: string`
  - необязательный параметр
  - путь к `.feature` файлу
  - если указан, файл сначала открывается в редакторе, затем проверяется синтаксис

Что проверяется:

- неизвестные шаги
- структурные ошибки Gherkin
- ошибки ключевых слов

Формат ответа:

- Markdown
- при наличии `filePath` выводится путь к проверенному файлу
- выводится признак корректности синтаксиса
- выводится количество проблем
- при наличии ошибок выводится список проблем с номером строки

Пример вызова:

```json
{}
```

```json
{"filePath": "C:\\Tests\\features\\draft.feature"}
```

- содержимое активного документа (если `includeContent = true`)
- позиция курсора (строка, колонка)
- список ошибок из `ДанныеОшибокVanessaEditor`

Формат ответа:

- Markdown

Пример вызова:

### 7. `getFormAnalysis`

- BSL-функция описания: `MCPИнструментGetFormAnalysis()`
- BSL-обработчик: `MCPОбработатьGetFormAnalysis(ИдентификаторЗапроса, Аргументы)`
- Назначение: вернуть состояние текущей формы тестируемого приложения. Может вернуть дерево элементов, Gherkin-представление или оба.
- Аннотации: `readOnlyHint`
- Требуется: подключённый TestClient

Поддерживаемые параметры:

- `format: string`
  - необязательный параметр
  - `"full"` (по умолчанию) — дерево элементов + Gherkin
  - `"gherkin"` — только Gherkin-шаги описания формы
  - `"elements"` — только дерево элементов

Что входит в ответ:

- имя формы и заголовок окна
- Gherkin-шаги, описывающие текущее состояние формы
- дерево элементов с типами, значениями, видимостью

Формат ответа:

- Markdown
- секции зависят от `format`
- при отсутствии данных: подсказки «Следующие шаги» (`connectTestClient`, повторить `getFormAnalysis`)

Источник BSL:

- `ПолучитьИзмененияФормы("Gherkin", ДопПараметры)` — для Gherkin
- `ПолучитьТекущуюФормуTestClient()` — для имени формы

Пример вызова:

```json
{}
```

```json
{"format": "gherkin"}
```

```json
{"format": "elements"}
```

### 8. `executeStep`

- BSL-функция описания: `MCPИнструментExecuteStep()`
- BSL-обработчик: `MCPОбработатьExecuteStep(ИдентификаторЗапроса, Аргументы)`
- Таймер ожидания: `MCPОжиданиеВыполненияШагаТаймер()`
- Назначение: выполнить произвольный текст шага или текущий выделенный шаг в дереве тестов.
- Аннотации: `destructiveHint`
- Требуется: подключённый TestClient

Поддерживаемые параметры:

- `stepText: string`
  - необязательный параметр
  - полный текст шага для выполнения
  - если не указан, выполняется текущий выделенный шаг в дереве или редакторе

Что входит в ответ:

- статус выполнения (Success, Failed, Broken, Pending)
- режим выполнения: произвольный шаг или текущий выделенный шаг
- время выполнения
- сообщение об ошибке (при наличии)

Формат ответа:

- Markdown

Особенности:

- DLL удерживает HTTP-соединение до получения ответа
- таймер каждые 500мс проверяет `Объект.ИдетВыполнениеСценариев`
- результат читается из `МассивРезультатПрохожденияТестовСценария`

Источник BSL:

- `Шаг(Стр, ВыполнятьЧерезВременнуюФичу = Ложь, ДопПараметры = Неопределено)`
- `ВыполнитьОдинШаг()`

Пример вызова:

```json
{}
```

```json
{"stepText": "И я нажимаю на кнопку с именем \"ФормаЗаписать\""}
```

### 9. `runScenario`

- BSL-функция описания: `MCPИнструментRunScenario()`
- BSL-обработчик: `MCPОбработатьRunScenario(ИдентификаторЗапроса, Аргументы)`
- Таймер ожидания: `MCPОжиданиеВыполненияСценарияТаймер()`
- Отправка результата: `MCPОтправитьРезультатСценария(ИдентификаторЗапроса)`
- Назначение: запустить выполнение сценариев в одном из четырёх режимов. Отправляет прогресс через SendProgress.
- Аннотации: `destructiveHint`

Поддерживаемые параметры:

- `mode: string`
  - необязательный параметр
  - режим запуска:
    - `"selected"` (по умолчанию) — выполнить выделенный сценарий
    - `"all"` — выполнить все сценарии
    - `"reloadAndRun"` — перезагрузить .feature с диска и выполнить
    - `"fromCurrentStep"` — выполнить с текущего шага
  - по умолчанию используется `"selected"`

Что входит в ответ:

- общий статус (Passed/Failed)
- количество пройденных/упавших сценариев
- общее время выполнения
- текст ошибки (при наличии)
- результаты по шагам

Формат ответа:

- Markdown

Прогресс:

- таймер каждые 500мс проверяет `Объект.ИдетВыполнениеСценариев`
- отправляет прогресс: `Шаг N/M: имяШага`
- по завершении возвращает итоговый результат

Режимы:

| mode | BSL-вызов |
|------|-----------|
| `"selected"` | `ВыполнитьВыделенныйСценарий()` |
| `"all"` | `КомандаВыполнитьСценарии()` |
| `"reloadAndRun"` | `ПерезагрузитьИВыполнитьДанныйСценарий()` |
| `"fromCurrentStep"` | `ВыполнитьДанныйСценарийСТекущегоШага()` |

Пример вызова:

```json
{}
```

```json
{"mode": "reloadAndRun"}
```

```json
{"mode": "all"}
```

### 12. `takeScreenshot`

- BSL-функция описания: `MCPИнструментTakeScreenshot()`
- BSL-обработчик: `MCPОбработатьTakeScreenshot(ИдентификаторЗапроса, Аргументы)`
- Callback-обработчик: `MCPПолученСнимокЭкранаОбработчикОповещения(ДвоичныеДанные, ПараметрыВызова, ДополнительныеПараметры)`
- Назначение: сделать скриншот именно клиента тестирования и вернуть его прямо в ответе MCP.
- Аннотации: `readOnlyHint`

Поддерживаемые параметры:

- `strategy: number`
  - необязательный параметр
  - способ снятия скриншота:
    - `0` — стандартный (по умолчанию)
    - `1` — после модального диалога
    - `2` — из окон процесса

Требуется:

- подключённый и запущенный TestClient

Что входит в ответ:

- Markdown-подтверждение успешного снятия скриншота клиента тестирования
- встроенное изображение PNG в MCP `content` как элемент `type: image`
- использованная стратегия
- статус операции

Формат ответа:

- Markdown + image content
- base64 PNG нормализуется в одну строку без `CR/LF`, чтобы MCP-клиент корректно декодировал изображение

Особенности реализации:

- вызов асинхронный: скриншот снимается через VanessaExt callback и затем отправляется в исходный MCP-запрос
- скриншот снимается только для процесса текущего клиента тестирования
- если TestClient не подключён или не запущен, инструмент возвращает ошибку с подсказкой сначала вызвать `connectTestClient`
- если VanessaExt не загружен или снимок не получен, возвращается текст ошибки с подсказкой проверить настройки раздела «Скриншоты»

Источник BSL: `MCPОбработатьTakeScreenshot(...)`, `MCPПолученСнимокЭкранаОбработчикОповещения(...)`, `MCPОтправитьРезультатИнструментаСИзображением(...)`

Пример вызова:

```json
{}
```

```json
{"strategy": 2}
```

### 13. `manageVariables`

- BSL-функция описания: `MCPИнструментManageVariables()`
- BSL-обработчик: `MCPОбработатьManageVariables(ИдентификаторЗапроса, Аргументы)`
- Назначение: чтение, установка и удаление переменных тестового контекста.
- Аннотации: `idempotentHint` (для get/set), `destructiveHint` (для delete)

Поддерживаемые параметры:

- `action: string`
  - необязательный параметр
  - `"get"` (по умолчанию) — получить переменные
  - `"set"` — установить переменную
  - `"delete"` — удалить переменную
- `name: string`
  - обязательный для `set` и `delete`
  - имя переменной
  - для `get` без `name` — возвращает все переменные
  - для `get` с `name` — возвращает одну переменную
- `value: string`
  - обязательный для `set`
  - значение переменной

Что входит в ответ:

- для `get` — таблица переменных или значение одной
- для `set` / `delete` — статус операции

Формат ответа:

- Markdown

Источник BSL:

- get (все): итерация по `ОбъектКонтекст` + `ОбъектКонтекстСохраняемый`
- get (одна): `ЗначениеПеременной(name)`
- set: `СохранитьЗначениеПеременнойВКонтекст(name, value)`
- delete: `ОбъектКонтекст.Удалить(name)`

Пример вызова:

```json
{}
```

```json
{"action": "get", "name": "ТекущийКонтрагент"}
```

```json
{"action": "set", "name": "МояПеременная", "value": "Значение123"}
```

```json
{"action": "delete", "name": "МояПеременная"}
```

### 14. `manageBreakpoints`

- BSL-функция описания: `MCPИнструментManageBreakpoints()`
- BSL-обработчик: `MCPОбработатьManageBreakpoints(ИдентификаторЗапроса, Аргументы)`
- Назначение: установка, снятие и просмотр брейкпоинтов в Gherkin-сценариях.
- Аннотации: `idempotentHint`

Поддерживаемые параметры:

- `action: string`
  - необязательный параметр
  - `"toggle"` (по умолчанию) — переключить точку останова
  - `"removeAll"` — удалить все точки останова
  - `"list"` — показать список точек останова
- `line: number`
  - необязательный параметр
  - номер строки для toggle (если не указан — текущая позиция курсора)

Что входит в ответ:

- для `toggle` — номер строки, установлен ли брейкпоинт
- для `removeAll` — количество удалённых
- для `list` — список всех брейкпоинтов с номерами строк

Формат ответа:

- Markdown

Источник BSL:

- toggle: `ПолучитьVanessaEditor().toggleBreakpoint(line)` или `ОбработатьУстановкуСнятиеБрейкпоинта()`
- list: `Брейкпоинты()`
- removeAll: `VanessaEditorRemoveBreakPoints()`

Пример вызова:

```json
{}
```

```json
{"action": "toggle", "line": 15}
```

```json
{"action": "list"}
```

```json
{"action": "removeAll"}
```

### 15. `loadFeatures`

- BSL-функция описания: `MCPИнструментLoadFeatures()`
- BSL-обработчик: `MCPОбработатьLoadFeatures(ИдентификаторЗапроса, Аргументы)`
- Назначение: загрузить или перезагрузить .feature файлы в дерево тестов. Используется после редактирования файлов AI-агентом.
- Аннотации: `destructiveHint`

Поддерживаемые параметры:

- `path: string`
  - необязательный параметр
  - путь к каталогу или файлу для загрузки
  - если не указан — перезагрузка текущего `КаталогФич`

Что входит в ответ:

- статус загрузки
- путь к каталогу фич

Формат ответа:

- Markdown

Источник BSL: устанавливает `Объект.КаталогФич = path`, затем вызывает `КомандаПерезагрузить()`

Пример вызова:

```json
{}
```

```json
{"path": "C:\\Tests\\features"}
```

## Ресурсы (Resources)

Ресурсы — read-only данные, доступные через URI без вызова инструмента.

### R1. `va://state`

- BSL-обработчик: `MCPОбработатьРесурсState(ИдентификаторЗапроса)`
- Назначение: полное состояние Vanessa Automation в формате Markdown
- MIME: `text/markdown`

Содержимое:

- текущая фича, сценарий, шаг
- статус выполнения
- настройки (каталог фич, язык, профиль TestClient)

### R2. `va://variables`

- BSL-обработчик: `MCPОбработатьРесурсVariables(ИдентификаторЗапроса)`
- Назначение: все переменные тестового контекста
- MIME: `text/markdown`

Содержимое:

- таблица всех переменных из `ОбъектКонтекст` и `ОбъектКонтекстСохраняемый`

## Промпты (Prompts)

Промпты — шаблоны системных сообщений для AI с подставленным контекстом.

### P1. `writeScenario`

- BSL-обработчик: `MCPОбработатьПромптWriteScenario(ИдентификаторЗапроса, Аргументы)`
- Назначение: системный промпт с инструкциями по написанию BDD-сценариев

Параметры:

- `description: string` — описание тестируемого бизнес-процесса (обязательный)
- `language: string` — язык Gherkin (необязательный, по умолчанию — текущий язык фичи)

Содержимое промпта:

- инструкции по формату Gherkin
- ключевые слова на нужном языке
- стиль форматирования VA
- описание задачи пользователя

### P2. `analyzeFailedTest`

- BSL-обработчик: `MCPОбработатьПромптAnalyzeFailedTest(ИдентификаторЗапроса, Аргументы)`
- Назначение: системный промпт для анализа упавших тестов

Параметры:

- `errorContext: string` — дополнительный контекст ошибки (необязательный)

Содержимое промпта:

- текущее состояние VA (фича, сценарий, шаг, ошибка)
- инструкции по диагностике
- советы по использованию инструментов VA
