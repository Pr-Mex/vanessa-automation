# Правила работы над задачами проекта Vanessa Automation

Документ для AI-агентов: устройство проекта, обязательные правила и типовые подводные камни.

## 1. Запуск и сборка

- VA запускать в клиенте тестирования; для работы с MCP web-клиент не используем. Команда «Открыть vanessa automation VAEditor» в командном интерфейсе служебной конфигурации.
- Нужен менеджер тестирования — передавать ключ `/TestManager` клиенту тестирования (см. §9).
- Сеанс VA, подключённый по MCP, — управляющий: не трогать без необходимости. Исключение — доработка MCP: перезапуск инструментом `restart_vanessa` (VA внутри основного менеджера тестирования). Инструмент не работает, если VA открыта не из `.epf`; форма закрывается без сохранения, TestClient после перезапуска подключать заново.
- Сборка обработок проекта — `Compile.bat` в корне (нужны OneScript и доступ к сети для пакетов).

## 2. Устройство проекта

### 2.1. Архитектура

- VA — BDD-фреймворк для 1С: фичи Gherkin исполняются в клиенте тестирования (TestClient). Поставка — внешняя обработка `VanessaAutomation\`; шаги — `features\Libraries\`.
- `VanessaAutomation\Forms\УправляемаяФорма\Ext\Form\Module.bsl` — фасад: состояние в экспортных переменных модуля; работа делегируется субмодулям:

| Переменная | Модуль | Ответственность |
|---|---|---|
| `МодульКлиентТестирования` | `Forms\КлиентТестирования\` | ТестируемоеПриложение/ТестируемаяФорма: элементы, таблицы, окна, клики |
| `МодульМобильноеТестирование` | `Forms\МобильноеТестирование\` | мобильные клиенты (Android, adb) |
| `МодульUIAutomation` | `Forms\UIAutomation\` | эмуляция движения мыши (VanessaExt, Windows) |
| `МодульПлагины` | `Forms\Плагины\` | плагины, ленивая загрузка через `МодульПлагины()` |

- В субмодуле `Ванесса` — контекст главной формы; общее — через `Ванесса.*`. Инициализация: `&НаКлиенте Функция ИнициализацияФормы(ВладелецФормы) Экспорт` → `Ванесса = ВладелецФормы`.
- Цепочка шага: фича → модуль библиотеки `features\Libraries\<Библиотека>\step_definitions\...` → `Ванесса.<Метод>` (делегат в фасаде) → `Модуль<...>.<Метод>` (реализация). MCPVA вызывает те же методы фасада — правка в субмодуле действует для UITestRunner, MCPVA и VA.
- Новый метод `Ванесса.*` требует двух мест: реализация в субмодуле + делегат в фасаде.
- Регистрация шага: `Ванесса.ДобавитьШагВМассивТестов(ВсеТесты, "ИмяФункции(Парам01)", "ИмяФункции", "Текст шага", "Описание/примеры")`.
- Прочие формы: `MCPVA`, `MCPVA_Служебный` (MCP-инструменты), `UIAutomation`, `ПарсерФич`.

### 2.2. Файлы

- `VanessaAutomation\Forms\<Форма>\Ext\Form\Module.bsl` — модуль формы; `Ext\Form.xml` — метаданные, включая списки выбора (например, `ТипКлиента`).
- `features\Libraries\<Библиотека>\step_definitions\...` — шаги; `features\Core\...` — фичи; `_en.feature` — англ. варианты.
- `docs\` — документация: `CommandSetting`, `ReturnStatus\ReturnStatus.md`, `Changelog.md`, `FAQ\Режим совместимости 8.2.md`, `mobile\mobile.md`.
- `docs\JsonParams\JsonParamsRU.md`, `JsonParamsEN.md` — генерируются по кнопке «Создать инструкцию по описанию элементов» (`СоздатьИнструкциюПоОписаниюЭлементов`, закладка «Служебная»); вручную не править. За один запуск обновляется только файл текущего языка (`ЯзыкГенератораGherkin`). Описание параметра задаётся в заголовке расширенной подсказки элемента формы (`РасширеннаяПодсказка.Заголовок`) сразу на всех языках формы (минимум RU/EN); параметр должен быть зарегистрирован в `КоллекцияКомандЗапуска()`, иначе генерация падает. Проверка — `features\Core\MainForm\ПроверкаФормированияФайлаJsonParams.feature`.
- Макеты переводов `locales\Messages\Templates\<lang>` и `locales\Steps\Templates\<lang>` вручную не править: переводы дополняются отдельно (для сообщений — сразу для всех языков: `tools\Translate\ПомощникПеревода`, `tools\Translate\fix_translations\fix_translations.py`; для шагов — отдельный процесс). `VanessaAutomation\Templates\ШаблонПеревода` — макет таблицы переводов шагов, а не хранилище переводов. Новые строки в коде — по-русски, см. §10.
- `temp\` — рабочие файлы, не для поставки.

### 2.3. Ключевые факты

- `Версия851ИлиВыше` и родственные вычисляются один раз процедурой `ОпределениеВерсииПлатформы()` через `Новый СистемнаяИнформация` — это версия платформы самого VA, не TestClient.
- Типы клиента: `Тонкий`, `Толстый`, `Web`, `МобильныйКлиент`, `МобильноеПриложение`, `МобильныйКлиентАвтономный`, `ОбычноеПриложение`.
- Данные клиентов — таблица `ДанныеКлиентовТестирования` (реквизит формы), заполняется процедурой `ПрочитатьДанныеКлиентовТестирования`. `ТекущиеДанныеКлиентаТестирования()` ищет текущую строку → сохранённый контекст по `Имя`/`Синоним` → строку с `ЭтотКлиент = Истина` и может вернуть `Неопределено`; `ЭтоМобильныйКлиентТестирования()` этого не обрабатывает.
- Мобильные типы: `МобильныйКлиент` → `com.e1c.mobile.client`, `МобильныйКлиентАвтономный` → `com.e1c.mobile.standalone`, `МобильноеПриложение` → `com.e1c.mobile`; запуск/остановка через `adb`; требования — `docs\mobile\mobile.md`.
- При добавлении мобильного типа обновлять обе проверки: подстроку «мобильный» (`Найти(НРег(...))`) и явное перечисление трёх мобильных типов.
- Эмуляция движения мыши в UIAutomation включается только при `Ванесса.Объект.ЭмулироватьДвиженияМышкиVanessaExt И НЕ Ванесса.ТекущийTestclientЭтоWebКлиент И Ванесса.Объект.ИспользоватьКомпонентуVanessaExt И Ванесса.Объект.ИспользоватьUIAutomation`; тело — в `Попытка`. `ПереместитьКурсорКТекущемуЭлементу` выходит сразу, если эмуляция мыши в браузере не включена.
- **По умолчанию TestClient подключается к базе менеджера VA.** Это правило для любого подключения, а не только для шагов библиотеки «Объекты конфигурации»: эти шаги выполняются в базе менеджера, и при другой базе тест видит чужие данные. Подключение к другой базе допустимо, только если пользователь явно указал её в задаче или отдельной инструкции.
  - Перед `manage_test_client(action='connect')` сравнить строку подключения профиля (`manage_test_client_profiles(action='get')`) со строкой подключения менеджера (`get_environment_data` → «Строка соединения с информационной базой»).
  - Если базы различаются и пользователь явно не указал эту базу — подключение не выполнять, сообщить обе строки подключения и спросить пользователя.
  - Служебные базы (`tools\ServiceBases\...`) — общие тестовые стенды. Подключать к ним TestClient из управляющего сеанса MCP без отдельного разрешения пользователя нельзя.
  - Ключ `/TestManager` не является условием подключения к базе. Он нужен, только когда клиент тестирования должен одновременно выполнять функции менеджера тестирования (например, для шагов, которым нужны типы `ТестируемаяФорма`/`ТестируемаяГруппаФормы`). Наличие или отсутствие `/TestManager` не делает профиль подходящим или неподходящим для выбранной базы.

### 2.4. Фичи с временными пользователями ИБ

- `Контекст` выполняется перед каждым сценарием, включая сценарий очистки: создание пользователей и подключение клиента в Контексте повторяются. Побочные эффекты Контекста должны быть идемпотентны.
- Временный пользователь создаётся в Контексте до открытия TestClient; для него создаётся отдельный профиль шагом `я подключаю TestClient "<Профиль>" логин "<Логин>" пароль "<Пароль>"`. Общий профиль «Этот клиент» не менять.
- Шаги `в базе есть пользователь` и `Я удаляю пользователя` выполняются в базе менеджера VA; база TestClient должна совпадать с базой менеджера.
- Очистка — отдельный последний сценарий: закрыть клиент временного пользователя, удалить всех временных пользователей, активизировать строку «Этот клиент». Так очистка выполнится и при падении основного сценария.
- Удаление последнего администратора разрешено, если менеджер запущен без пользователя (привилегированный сеанс). Это условие таких фич.
- Профили, созданные шагом подключения, после прогона остаются в таблице клиентов; активной должна быть строка «Этот клиент».

## 3. Командная строка

- Параметры читает `ЗначениеПараметраЗапуска`; приоритет: переменная среды `VANESSA_КЛЮЧ` → `/C` → `VAParams.json`. Новый параметр запрашивать по RU+EN имени (например, `QuietInstallVanessaExt`/`ТихаяУстановкаVanessaExt`); регистрация в `КоллекцияКомандЗапуска` не обязательна.
- Парсер `/C` — `ПолучитьСтруктуруПараметров`: разделитель только `;`, кавычки не обрабатываются, `\;` — только если строка содержит и `{`, и `[`; флаг без значения = Истина; ключи — точный регистр или ВРег.
- `ЗначениеСтрокиВБулево` искажает строки `"1"`, `"0"`, `"истина"`, `"ложь"`, `"true"`, `"false"` — такие значения в путях не использовать; ограничение документировать.
- Списки — через запятую; в `ExtensionPath` пути разделяются `|`, сам `|` внутри пути недопустим, точка с запятой в пути не поддерживается.
- Пакетный запуск — `ЗапускВРежимеКоманднойСтроки`: нужны `StartFeaturePlayer` (или `GetStepsCache`) и файл VAParams. Вход: `ЧтениеПараметровПриОткрытии.ПриОткрытии` → `УправляемаяФорма.ПриОткрытии` → `ПослеОткрытияФормы2` → `ПослеОткрытияФормыПродолжение` → `ЗапускВРежимеКоманднойСтроки`.
- Флаги «выполнить и закрыть» — в начале `ПослеОткрытияФормы2`; ранний `Возврат` пропускает остальные ветки и тело (обучение, `ЗаполнитьДанныеТекущейИнфобазы`, `ФормаVanessaAutomationОткрылась`).
- Закрытие — `ОбработчикОжиданияПрекратитьРаботуСистемы` → `ПрекратитьРаботуСеансаVanessaAutomation` (`глЗавершениеРаботы = Истина`, `ПрекратитьРаботуСистемы()`); диалога «данные изменены» нет, код возврата процесса не устанавливается — результат передаётся файлом.
- Статус для CI — файл: `ВыгружатьСтатусВыполненияСценариевВФайл` + `ПутьКФайлуДляВыгрузкиСтатусаВыполненияСценариев`, коды 0–4 в `docs\ReturnStatus\ReturnStatus.md`; новые коды документировать там же. Без `createlogs` процедура молча выходит; новый механизм делать отдельной процедурой с проверками путей.
- Установка расширений (`InstallExtensionsAndClose`): несовместим с `StartFeaturePlayer` (остальные параметры игнорируются, кроме `ExtensionPath` и `InstallExtensionsResult`); `ExtensionPath` — пути `.cfe` через `|`; `InstallExtensionsResult` — файл результата (`0` — успешно, `5` — ошибка); нужно право `АдминистрированиеРасширенийКонфигурации`.
- Механика установки: в сеансе VA `РасширенияКонфигурации.Создать/Получить/ПроверитьВозможностьПрименения/Записать`; имя из cfe, идемпотентно по имени; `ПредупреждатьОбОпасныхДействиях = Ложь`; каждое расширение в `Попытка`; критичные ошибки — исключение, некритичные — в результат; результат каждого расширения — в журнал регистрации; для БСП — `ОбновитьПараметрыРаботыВерсийРасширений`; документация — `docs\CommandSetting`.

- После доработки — grep по полному списку из `docs\FAQ\Режим совместимости 8.2.md`.

## 5. Клиент/сервер в модуле формы

- Обёртки: `Локализовать`/`ЛокализоватьСервер`, `СообщитьПользователю`, `ЗаписатьЛогВЖРОшибка`, `ПодставитьПараметрыВСтроку`, `ПреобразоватьПутьСТочкамиКНормальномуПути`, `SleepOnServer`, `ЭтоLinux`.
- Есть мнение (требует проверки), что чтение переменной модуля формы из `&НаСервере` зависит от персистентности контекста; надёжнее передавать параметром или через `Объект.ДополнительныеПараметры`.
- Файлы: чтение — на клиенте; тяжёлые операции и монопольный режим — на сервере; guard'ы — в серверном вызове до цикла.
- Монопольный режим снимать при любом исходе (`Попытка ... Исключение Снять; ВызватьИсключение; КонецПопытки`), лимит попыток с паузой `SleepOnServer`, при исчерпании — исключение. Не копировать схему 10000 попыток × 5 с из сторонней обработки установки расширений.

## 6. MCP

- Клиент для незаданных опциональных параметров передаёт `null` → в 1С `Неопределено`. Проверять `<> "" И <> Null И <> Неопределено` (`Неопределено <> Null` — истина). Образец — `get_table_data`.
- Новый инструмент: описание — в `MCPVA_Служебный`, обработчик — в `MCPVA`; без регистрации в обоих инструмент не появится.
- Любой метод VanessaExt вызывается синхронно и асинхронно: `НачатьВызов<Метод>` / `НачатьПолучение<Свойство>`; асинхронные обёртки генерирует платформа.
- Проверка занятости озвучки (`ВоспроизводитсяМедиа`) не требует UI-потока; событие `MEDIA_FINISHED` приходит перед закрытием медиа.
- Отложенный ответ: инструмент с `Асинхронный = Истина`; обработчик сохраняет id (`УстановитьИдентификаторЗадачиMCP`), запускает `НачатьВызов*` в `Попытка`, возвращает `Неопределено`; колбэк `(РезультатВызова, ПараметрыВызова, ДопПараметры)` вызывает `ЗавершитьВызовИнструментаУспешно/СОшибкой` и обнуляет id. Примеры: `get_window_list_os`, `get_process_list_os`.
- Валидационные ветки «асинхронного» инструмента могут отвечать сразу `ОшибкаИнструмента("INVALID_PARAMS"/"ACTION_FAILED", ...)`.
- Ограничение: одна переменная `ИдентификаторЗадачиMCP` — два одновременных отложенных вызова затмят друг друга.
- Тело колбэка целиком в `Попытка`, иначе запрос MCP останется без ответа.
- Долг NoSync: прямые синхронные вызовы компоненты в `MCPVA` и `MCPVA_Служебный` (например, `ПолучитьСписокОкон`, `ПолучитьСнимокОкна`); новые вызовы делать асинхронными.
- Каскадные fallback-и (`null→0→50`) скрывают сломанные ветки — проверять сквозное поведение параметра (прецедент `search_for_steps_by_keywords`).
- `get_process_list_os`: фильтр — подстрока или маска `*` через `СтрокаСоответствуетШаблону` (regex экранируется, регистр не важен), `limit=0` — все, `only_1c=true` — только процессы 1С; ошибки — `ОшибкаИнструмента`.
- `speak_text`: проверка занятости — `НачатьВызовВоспроизводитсяМедиа`, воспроизведение — `НачатьВызовВоспроизвестиМедиа`, ответ инструмента отложенный; кеш озвучки общий, наружу отдаётся копия файла.
- Проверка правок: пересборка epf → `restart_vanessa` → живые вызовы; смотреть заголовки ответов с фактическими значениями («Лимит: N» / «Найдено: X. Показано: Y»).
- При правке MCP поднимать «Версию MCP» (`ВерсияMCP()`); служебные записи — `MCPЗаписатьСлужебныеДанные()`, в `MCPVA_Служебный` — `MCPЗаписатьСлужебныеДанныеБезопасно`.

## 7. Файловые операции

В NoSync-режиме (`ЗапрещеныСинхронныеВызовы = Истина`) платформенные файловые функции падают. Использовать обёртки, которые выбирают команду ОС:
- `КопироватьФайлКомандаСистемы`, `ПереместитьФайлКомандаСистемы`, `УдалитьФайлыКомандаСистемы`, `СоздатьКаталогКомандаСистемы`, `ФайлСуществуетКомандаСистемы`.
- `УдалитьФайлыКомандаСистемы` в обычном режиме не защищён от отсутствующего файла — сначала `ФайлСуществуетКомандаСистемы`.
- Если файловая операция не работает в NoSync — проверить, не вызвана ли платформенная функция напрямую.

## 8. Новые шаги и Gherkin

- Сниппет — второй параметр `ДобавитьШагВМассивТестов` (после `МассивТестов`). Имя — из литеральных слов текста шага после ключевого слова Gherkin. Значения параметров не входят; литеральные слова между параметрами и после них входят. Первая буква каждого литерального слова заглавная, пробелы убраны.
- Пример: `И я запоминаю случайную дату рождения старше "Возраст" лет в переменную "ИмяПеременной"` → `ЯЗапоминаюСлучайнуюДатуРожденияСтаршеЛетВПеременную(Парам01,Парам02)`.
- Имя по смыслу не придумывать. Признак ошибки: `search_for_steps_by_keywords` шаг находит, а `check_syntax`/`run_scenario` пишет «Шаг не найден в библиотеке известных шагов».
- `ИмяПроцедуры` держать равным сниппету. Логика — `ПарсерФич`: `ПолучитьStepDefinitionПоСтроке`, `РассчитатьStepDefinition`, `StepDefinitionИзТаблицы`, `ПолучитьДанныеШагаИзСтроки` (`СнипетБезПараметров`).
- Проверка нового шага: пересобрать epf → перезагрузить VA → `check_syntax` на фиче с шагом.
- Апострофы внутри параметра в двойных кавычках экранировать одним `\`:
  `И MCP-инструмент вернул ошибку "INVALID_PARAMS" с текстом, содержащим "\'get_list\', \'get\', \'add\', \'edit\'"`.
  Без этого legacy-парсер подменяет фрагменты placeholder'ами `||ПараметрСтрокаА||` / `||ПараметрСтрокаК||`.
- `check_syntax` дефект апострофов не видит — нужен живой прогон; для проверки использовать шаг с двумя параметрами.
- Порядок проходов парсера (`"` раньше `'`) не менять: иначе дефект перейдёт на фичи, где внутри `'...'` используются `"..."`.

## 9. `/TestManager` и ошибка «Тип не определен (ТестируемаяГруппаФормы)»

- Типы `ТестируемаяФорма` и `ТестируемаяГруппаФормы` есть только в сеансе менеджера тестирования. Без `/TestManager` `Тип("ТестируемаяГруппаФормы")` падает во время выполнения (`VanessaAutomation\Forms\КлиентТестирования\Ext\Form\Module.bsl`, `ОбработатьСменуАктивногоОкна`).
- Тип используется в `КлиентТестирования` массово — точечная замена строки не поможет; модуль рассчитан на `/TestManager`.
- Проверка: в командной строке процесса (`get_process_list_os(only_1c=true)`) должен быть `/TestManager`; в профиле клиента в «Дополнительных параметрах» — `/TestManager`; подключаться этим профилем.
- Диагностика: в журнале регистрации искать текст ошибки и `ДопПараметрыПодключения` без `/TestManager`.
- Правильный запуск: сценарий `Запуск промежуточного менеджера тестирования` (`features\Core\VAEditor\АктуализацяТестов.feature`) или шаг `ЯОткрылНовыйСеансTestClientКакTestManagerИлиПодключилУжеСуществующийБезЗагрузкиНастроек`.
- `/TestManager` не удалять как «лишний ключ».
- С `/TestManager` служебная фича закрывает клиент-исполнитель, новый клиент запускается без ключа, менеджер теряет соединение и `ФлагСценарииВыполнены` падает по таймауту. Практическое правило: не закрывать клиент-исполнитель в служебной фиче; если закрывать — запускать новый с `/TestManager` или выносить в отдельный сеанс.
- Увидели ошибку типа — сначала проверять `/TestManager`, а не искать дефект в шаге; таймаут при наличии ключа — другая диагностика.

## 10. Стиль кода

- Табуляция; `КонецЕсли;`, `КонецЦикла;` с точкой с запятой; `КонецФункции`, `КонецПроцедуры` — без.
- Комментарии минимальны; над экспортными процедурами — однострочный заголовок. Тесты — с подробными комментариями.
- Области: `#Область TestClient` и т.п.
- Локализация: `Ванесса.Локализовать(...)`, `Ванесса.ПолучитьТекстСообщенияПользователю(...)`, подстановка `СтрЗаменить(Текст, "%1", ...)`.
- Особенности 1С: у соответствия нет метода `Свойство` (проверять `Получить(Ключ) = Неопределено`); нельзя переменную с именем `Объект`; `СтрНайти` и `Найти` сравнивают с учётом регистра; поиск файлов — только `НайтиФайлы`.

- После создания или правки feature-файла, если доступен MCP, выполнять `check_syntax` по этому файлу: он ловит неизвестные шаги, структурные ошибки и ошибки ключевых слов до запуска. Если MCP недоступен, проверять синтаксис доступным способом.
